# GapProof Canonical Demo Fixture

작성 2026-08-02 · 녹화·심사에서 쓰는 **단 하나의 데모 경로**를 고정합니다.
화면이 바뀌면 이 문서도 같이 고쳐야 합니다.

---

## 1. 이것은 fixture 입니다 (내부 Evidence)

`?sample=1` 경로는 **실제 Solar API 를 호출하지 않습니다.**
`app/lib/samples.ts` 의 `SAMPLE_JOURNEY` 에 미리 적어 둔 결과를 그대로 보여 줍니다.

- 이 사실을 화면에서 숨기지 않습니다. 데모 구간 내내 상단에 초록 띠로
  **"샘플 체험 중 — 실제 분석이 아닙니다"** 가 떠 있고, 3단계 배너는 **"준비된 예시 결과"**,
  결과 카드 하단은 **"샘플 규칙 제안 → 사용자 확인 완료"** 로 찍힙니다.
- 분석 진행 화면의 제목도 샘플 모드에서는
  **"준비된 샘플 결과를 불러옵니다. 실제 분석은 아래 세 단계를 거칩니다."** 로 나옵니다.
- 실제 Solar 호출 경로는 접근 코드로 입장하는 `/demo` 에 그대로 살아 있습니다.
  같은 6단계 화면을 쓰고, 3단계 배너만 `Solar <모델명> 분석 완료` 로 바뀝니다.

**왜 fixture 로 촬영하는가:** 유료 API 호출이 촬영 중 실패하거나 지연되면 테이크가 깨지고,
모델 응답이 매번 달라 컷을 이어 붙일 수 없습니다. 심사자에게 보여 줄 것은
"이 흐름이 무엇을 하는가" 이므로, 결과가 고정된 경로가 녹화에 맞습니다.

## 3. 예상 분석 결과 (고정)

`SAMPLE_JOURNEY.claims` 3건. 전부 `tier: 0`, `confidence: "확인 필요"`, `status: "pending"` 으로 시작합니다.

| # | 역량 후보 | 원문 인용(근거) | AI가 읽은 결과 | 증거 강도 |
| --- | --- | --- | --- | --- |
| 1 | 반복 일정 조율과 규칙 만들기 | "매주 레이드 일정을 짜는 게 일이었어요. …시간표를 세 개 버전으로 만들어서 투표를 돌렸어요." | 원문에 결과까지 있음 | 보통 |
| 2 | 온보딩 문서 작성·개선 | "공략이랑 규칙을 문서로 만들었어요. …열 장 정도 됐어요." | 원문에 결과까지 있음 | 보통 |
| 3 | 기록 기반 갈등 중재 | "양쪽 얘기를 따로 다 듣고 분배 기록을 정리해서 보여줬어요." | 원문에 행동만 있음 | 약함 |

과장 주의 문구는 1번·3번에만 붙습니다(2번은 `overclaimRisk: null`).

## 4. 결과 화면 고정값

기본 선택값을 바꾸지 않고 진행했을 때 나오는 값입니다.

| 항목 | 값 |
| --- | --- |
| 목표직무 | **AI 서비스 기획자** (`ROLES[0]`, 기본 선택) |
| 확인된 역량 | 3단계에서 "맞습니다"를 누른 것만. Shot List 기준 **1개** |
| 대표 근거 | 확인한 첫 후보의 원문 인용 |
| 우선 격차 | 문제 정의·도메인 연결 (Lv.0/3) · 사용자 검증 (Lv.0/3) · AI·API 프로토타이핑 (Lv.1/3) |
| 증거 충족도 | **0%** (0 / 5 항목) — 링크를 붙이지 않았으므로 정상값입니다 |
| 이번 주 다음 행동 | **5명 인터뷰 후 인사이트 정리** (미니프로젝트, 기본 선택 `project`) |
| 카드 날짜 | 녹화 기기의 **오늘 날짜** |
| 카드 하단 | "샘플 규칙 제안 → 사용자 확인 완료" |

> 증거 충족도가 0% 로 나오는 것은 결함이 아닙니다. 확인 가능한 링크를 하나도 붙이지 않은
> 상태를 그대로 보여 주는 값이고, 화면에도 "채용 가능성·합격 가능성·적성을 뜻하지 않습니다"가
> 함께 적혀 있습니다. 내레이션에서 이 숫자를 성과처럼 말하지 마십시오.

## 5. 화면 순서와 예상 로딩 상태

| 단계 | 화면 | 로딩 | 스크롤 |
| --- | --- | --- | --- |
| 1 | 시작 (동의) | 없음 | 최상단 |
| 2 | 경험 입력 | 없음 | 최상단 (입력칸 자동 채움) |
| — | **분석 진행** | **2.4초 고정** · 3단계 순차 체크 | 자동으로 최상단 |
| 3 | 역량 확인 | 없음 | 최상단 |
| 4 | 먼저 알아보기 | 없음 | 자동으로 최상단 |
| 5 | 격차·행동 | 없음 | 최상단 |
| 6 | GapProof 결과 | 없음 | 자동으로 최상단 |

단계 전환 시 화면은 스스로 맨 위로 부드럽게 올라갑니다(`prefers-reduced-motion` 이면 즉시).
촬영 중 수동 스크롤과 겹치지 않게 하십시오.

### 분석 진행 3단계 (문구 고정)

1. 개인정보로 보이는 표현을 가립니다 — 이메일·전화번호·주민등록번호 형식을 분석 전에 가립니다.
2. 경험에서 역량 후보와 근거 문장을 찾습니다 — 원문 인용을 함께 붙여 최대 3개까지 만듭니다.
3. 인용이 원문에 실제로 있는지 확인합니다 — 원문에서 찾을 수 없는 문장은 근거로 쓰지 않고 버립니다.

이 세 단계는 `/api/analyze` 가 실제로 수행하는 순서와 같습니다
(`maskPII` → Solar 호출 → `sanitizeClaimsV2` 의 인용 정합 검증).
퍼센트 수치는 쓰지 않습니다 — 서버 진행률을 측정할 수단이 없기 때문입니다.

들어오지 않습니다. 1440 이 그 대비가 살면서 글자 크기도 유지되는 값입니다.

## 8. 재현 확인

이 fixture 와 실제 화면이 일치하는지 확인하는 방법:

```bash
npm run dev
# 다른 터미널에서
npx playwright test tests/e2e/user-flow.spec.ts tests/e2e/gate.spec.ts
```

수동 확인은 `GAPPROOF_RECORDING_RUNBOOK.md` §1-4 체크리스트를 쓰십시오.

시크릿 창에서 3회 반복했을 때 매번 같은 화면·같은 값이 나와야 합니다.
다르게 나온다면 localStorage 의 `gp_draft` 가 남아 있는 것입니다.
