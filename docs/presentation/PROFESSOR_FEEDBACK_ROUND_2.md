# GapProof 2차 피드백 보고 (Professor Feedback RC)

작성일 2026-07-25 · 기준: `rc/professor-feedback` 브랜치(RC — 운영 반영 전) · 저장소 github.com/forblune/gap-proof-mvp

## 1. 서비스 한 문장 소개

**GapProof는 경력이라고 생각하지 않았던 경험(돌봄·게임·아르바이트·독학·쉬었던 시기까지)에서 실제 행동을 근거로 역량 후보를 찾고, 사용자가 직접 확인한 증거만으로 직업 가설과 이번 주 작은 실험을 제안하는 Solar 기반 진로 탐색 도구입니다.** (취업 가능성·적성을 판정하지 않습니다.)

## 2. 1차 피드백 이후 변경사항

1차 제출 폴리시(#3~#26, 운영 배포까지)에 이어, 2차 피드백 전 **Professor Feedback RC**(#34~#47, Gate 0~10)로 핵심 사용자 경험을 재구축했습니다. 모든 작업은 Issue→브랜치→테스트·증거→PR로 기록되어 있습니다.

## 3. 핵심 사용자 흐름 (RC)

홈(설명 없는 이해) → 샘플 체험(무코드) 또는 데모 코드 입장 → 경험 입력(10,000자·예시 분리·AI 가져오기·파일) → V2 후보(사실 상태·행동·신호·원문 근거) → 사용자 확인·수정·거절(0개면 차단) → 근거 강도·과장 위험·직업 가설(판정 아님)·작은 실험 → 격차·이번 주 행동 → 증거카드·Gap Brief → 새 분석/나가기(draft 정리)

각 단계에서 AI는 제안만 하고, 확정·수정·거절·삭제는 전부 사용자가 합니다. 원문에 없는 인용은 코드가 폐기합니다.

## 4. 세심하게 만든 부분

- 게임→코치, SNS→마케터식 **단정을 코드로 차단**(가설에 근거·부족 증거 필수, 판정 어휘 폐기)
- 근거 강도를 모르면 "약함", 상태를 모르면 "부분 확인"으로 **과장 방지 방향 강등**
- 세션이 끊겨도 **작성물은 기기에 남고**, 재인증하면 그 자리로 — 안내 문구도 실동작과 일치할 때만 사용
- 샘플과 실제 분석의 3중 구분(스트립·notice·배지), 파일은 업로드 없이 브라우저 안에서만
- 모델 카드에서 검증 안 한 장점은 쓰지 않고 "평가 중"으로
- 파괴적 버튼은 결과로 명명("새 분석 시작하기") + 비가역 고지 확인창
- 처리방침·약관은 실제 데이터 흐름과 1:1(전문가 검토 전임을 그대로 표시)

## 5. 품질 검증 (전부 실기록)

- 자동 테스트 **32/32**(렌더·게이트·마스킹·한도·allowlist·draft·V2 검증·파일 검증)
- e2e 6스위트: draft 10/10 · 샘플 10/10+API 0회 · 입력 7/7 · 가져오기 9/9 · 모델 6/6 · QA 스윕 16항목
- RLS 실검증(Postgres 16): 사용자 격리·해시 초대·ledger·탈퇴 purge
- 접근성: 미명명 컨트롤 0·키보드 전용 STEP2 도달·focus-visible·reduced motion
- 운영 기준선(1차): 실 Solar 1회 검증·PII 화면/로그 0건·429+Retry-After 실측(버전 `cece759c` 유지 중)

## 6. 현재 한계 (정직 고지)

- RC는 아직 **운영 미반영**(재배포는 승인 대기) — 현재 운영은 1차 제출 버전
- 회원가입·저장은 로컬 기반까지(운영 Supabase·메일·콘솔은 승인 후), /privacy·/terms는 전문가 검토 전
- 실기기(아이폰·안드로이드·**카카오 인앱**)·실제 Solar V2 충실도·3분 실발화는 수동 검증 대기
- 전역 rate limit 고도화(#32)·온통청년 연동·PDF/DOCX 첨부는 후속
