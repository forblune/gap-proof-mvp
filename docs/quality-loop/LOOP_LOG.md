### 버그 발견 및 수정
`/how-it-works` 번호 배지 1차 구현에서 `display:grid` + `::before` 조합이 `::before`를 실제 그리드 아이템으로 취급해 본문 문단이 30px 폭 컬럼에 갇혀 세로로 한 글자씩 줄바꿈되는 렌더링 버그 발생. Playwright의 가로 오버플로 검사는 이 버그를 잡지 못함(가로 오버플로가 아니라 좁은 컬럼 내 줄바꿈이었기 때문) — 스크린샷 시각 확인으로만 발견. `position:absolute` 배지로 교체해 해결하고 재확인.

Loop 3 종료 시점 총점 71.8/100. FINAL_AUDIT.md가 명시한 미해결 권고 2건: (1) 홈 H1/H2는 Loop 1에서 세리프→산세리프로 전환됐지만 `/why`·`/technology`·`/how-it-works`·`/guide`의 `.info-section h2`·`.info-shell h1`, 데모 흐름의 `.gate-card h1`·`.claim-card h2`(및 `.consent-card h2` 등)는 여전히 Georgia 세리프 — 사이트 전역 일관성 미해결. (2) `/demo` STEP2(역량 확인) 카드가 필드 9개 × 카드 3개로 밀도가 높고 아이콘이 없음 — 세부 진단 항목 중 최저(콘텐츠 밀도 3.7/10). 사용자가 최종 보고서의 후속 제안("콘텐츠 밀도 해소, 전역 타이포그래피 통일")을 별도 루프로 승인.

### 변경 의도
1. `app/globals.css`의 11개 헤딩 셀렉터(`.hero h1, .section-head h1`, `.consent-card h2`, `.gate-card h1`, `.info-shell h1`, `.info-section h2`, `.map-grid h2`, `.action-title h2`, `.identity h2`, `.brief-section h2`, `.check-panel h3`, `.who-card h2`)에서 `font-family: Georgia, ...` 제거 → 산세리프 상속. Tailwind preflight가 헤딩 font-weight를 `inherit`로 리셋하므로 명시적 `font-weight`(h1급 700 · h2/h3급 650)를 추가해 굵기 위계는 유지.
2. 인용구 관련 5개 셀렉터(`.evidence-preview blockquote`, `.mini-evidence > span`, `.claim-card blockquote`, `.quote-block blockquote`, `.story-callout p`)는 "인용문은 편집적 세리프로 강조"라는 의도로 Georgia 유지.
3. `app/demo/page.tsx` STEP2 카드 5개 필드 라벨에 기존 아이콘(`fact-icons.tsx`)을 재사용해 부여: `IconQuestion`(더 확인하면 좋은 것) · `IconCheck`(확인된 행동) · `IconWarning`(과장 주의) · `IconCompass`(직업 가설) · `IconChecklist`(이번 주 작은 실험). 새 의미 발명 없이 홈페이지 가상 사례 카드와 동일한 아이콘 의미를 재사용.
4. CSS: `.follow-up b`를 `display:block` → `display:flex; align-items:center; gap:5px`로 변경(아이콘을 라벨과 나란히 배치하기 위함), 아이콘 크기 공유 규칙 추가.

### 수정한 파일
- `app/demo/page.tsx` — STEP2 5개 필드 라벨에 아이콘 컴포넌트 삽입(import 추가).
- `app/globals.css` — 11개 헤딩 셀렉터에서 Georgia 제거 + 명시적 font-weight 부여, `.follow-up b`/`.v2-line b`/`.v2-hypo > b` display 통일, 아이콘 크기 공유 규칙 추가.

### 버그 발견 및 수정 (커밋 전에 처리)
독립 재채점 과정에서 `.v2-line b`(확인된 행동·과장 주의·이번 주 작은 실험)와 `.v2-hypo > b`(직업 가설)에 삽입한 아이콘 4종이 라벨과 나란히 배치되지 않고 **라벨 위에 별도 줄로 렌더링**되는 버그를 발견. 원인: `.follow-up b`만 `display:flex`로 바뀌었고 `.v2-line b`(기존 `inline-block`)·`.v2-hypo > b`(기존 display 미지정)는 display가 그대로였는데, 프로젝트가 쓰는 Tailwind v4 preflight가 `svg{display:block}`을 강제해 non-flex 부모 안에서 아이콘이 블록 박스로 분리되며 텍스트 위로 밀려 올라감. 1440px·390px 양쪽에서 재현 확인(`getBoundingClientRect`로 svg와 text가 서로 다른 y좌표에 쌓여 있음을 실측). `screenshots.spec.ts`는 STEP2를 캡처하지 않고 `accessibility.spec.ts`는 `/demo` 게이트 화면만 검사해 자동화 테스트로는 잡히지 않는 사각지대였음(Loop 2의 파이프라인 그리드 버그와 동일한 패턴).

**수정**: `.v2-line b`, `.v2-hypo > b`에 `display:inline-flex; align-items:center; gap:5px;` 추가 — `.follow-up b`와 동일한 패턴으로 통일. 수정 후 `getBoundingClientRect` 재측정: 4개 필드 전부 `bHeight=17.59px`(아이콘 없는 "상황" 기준값과 동일)로 정상화, svg와 text가 같은 y좌표에서 나란히 배치됨을 확인. 390px에서도 재확인. 커밋에는 수정된 버전만 포함됨.
