## 강점 (건드리면 안 되는 것)

### 포지셔닝
- 홈 5번째 섹션의 가상 사례 3가지(게임 길드 일정 조율, 2년 간병, 카페 알바+SNS+영상편집)는 인용문·확인된 행동·역량 후보·근거 문장·과장 방지 문구·직업 가설·이번 주 실험까지 한 카드에 담아, 추상적 주장이 아닌 검증 가능한 문장 단위로 제시되는 이 프로젝트에서 가장 설득력 있는 파트입니다.
- 홈 "누구를 위한가" 섹션의 대상 6개와 `/who`의 카드 6개가 문구 수준까지 거의 동일해, 홈과 상세 페이지 간 타겟 설명이 흔들리지 않습니다.

- Solar Pro3/Pro2/Mini 같은 모델 선택을 사용자에게 노출하고 "실제 연결인지 샘플인지 화면 배지로 항상 구분한다"고 명시하는 등, 기술적 투명성을 마케팅 언어가 아니라 검증 가능한 사실로 서술합니다.

### 카피
- 전 페이지·데모 5단계에서 "!", "혁신", "최고", "보장", "100%" 같은 과장 표현이 전혀 발견되지 않았습니다.
- 홈 H1과 1차 CTA("내 경험에서 가능성 찾기 →")는 막연하지 않고 사용자가 얻는 것을 알려주는 강한 문구입니다.
- `/who`의 "지금 겪는 문제 / GapProof가 돕는 방식 / 기대할 수 있는 결과 / 대신 결정하지 않는 것" 4단 구조, `/guide`의 "할 일 / 왜 필요합니까? / 예상 시간" 구조는 사용자의 암묵적 질문에 먼저 답하는 좋은 온보딩 카피 패턴입니다.
- 데모 STEP2 역량 후보 카드의 "과장 주의" 마이크로카피, `/about`의 구체적 창업 계기 서술, STEP4의 행동 지향적 버튼 문구 모두 브랜드 원칙을 세부 카피 차원에서 실천하고 있습니다.

### SEO
- robots.txt(`Allow: /`, `Disallow: /api/`, `Sitemap:`)와 sitemap.xml(게이트 뒤 `/demo` 의도적 제외, 공개 9개 페이지 등록, 합리적 priority)이 의도대로 정확히 동작합니다.
- 공개 페이지 9개 전부 고유한 title·description·자기참조 canonical을 가지며, 모든 페이지에서 `<h1>` 정확히 1개와 레벨 건너뜀 없는 H1→H2 흐름을 서버 렌더·클라이언트 DOM 양쪽에서 확인했습니다.
- 장식용 SVG 아이콘은 예외 없이 `aria-hidden`, 유일한 아이콘 전용 버튼(테마 토글)에는 `aria-label`이 있으며, og:image가 선언된 1200x630과 정확히 일치합니다.
- Lighthouse를 오늘 직접 재측정한 결과 Accessibility 100/100, SEO 100/100을 `/`와 `/demo` 양쪽에서 확인했습니다.

## P0 — 즉시 수정 필요 (1건)

### 1. 리터럴 HTML 엔티티(`&ldquo;`/`&rdquo;`)가 화면에 그대로 노출됨
- **페이지**: `/technology`, `/how-it-works`
- **근거**: `/technology`의 "무저장 원칙" 카드 실제 렌더링 텍스트는 `경험 원문을 서버에 저장하지 않습니다. &ldquo;새 분석 시작하기&rdquo;는 화면의 모든 상태를 지웁니다.`이고, `/how-it-works`의 "삭제" 항목도 `&ldquo;새 분석 시작하기&rdquo;를 확인하면...`으로 동일하게 깨져 있습니다. 스크린샷으로 화면에 그대로 `&ldquo;`, `&rdquo;` 문자가 보이는 것을 확인했습니다. 원인은 두 파일(`app/technology/page.tsx:26`, `app/how-it-works/page.tsx:22`) 모두 JSX 텍스트 자식이 아니라 별도 배열의 문자열 리터럴(`detail: "...&ldquo;...&rdquo;..."`) 안에 엔티티 코드를 그대로 타이핑해 둔 것으로, JSX 텍스트 노드에 직접 쓴 동일 문구(`/about`, `/why`, `/demo:1133`)는 정상적으로 curly quote(" ")로 렌더링되어 대조됩니다.
- **영향**: 원래는 카피 분석에서 "high"로 분류된 항목이지만, 이 보고서에서는 P0로 재분류했습니다. 근거는 (1) 이것이 단순히 어색한 문구가 아니라 명백한 렌더링 버그이고, (2) 하필 "쓴 기술만 말하고 검증한 만큼만 주장합니다"라는 이 프로젝트의 신뢰성 핵심 메시지를 담은 페이지 자체에서 발생해 그 메시지의 설득력을 정면으로 훼손하며, (3) 심사·멘토링 공유가 목적인 프로젝트에서 지도교수가 가장 먼저, 가장 쉽게 발견할 수 있는 종류의 "QA를 안 한 것처럼 보이는" 오류이고, (4) 동시에 수정 비용이 리터럴 문자 두 개를 바꾸는 것뿐이라 즉시 처리 가치가 매우 높기 때문입니다. "제목·설명·버튼 문구가 자연스러운가"라는 사용자 목표를 두 페이지에서 직접적으로 해칩니다.
- **수정 방향**: 두 문자열 리터럴 안의 `&ldquo;`/`&rdquo;`를 실제 유니코드 curly quote 문자(" ")로 바꿉니다. JSX 텍스트 노드로 직접 옮겨 쓰는 방법도 가능하지만, 가장 빠른 수정은 문자열 리터럴 내 엔티티 코드를 실제 따옴표 문자로 치환하는 것입니다.
- **발견 관점**: 카피(copywriting) — 원 분석에서는 urgency "high"로 표기되었으나, 노출 지점이 신뢰성 핵심 메시지 페이지라는 점과 수정 비용 대비 파급력을 고려해 이 보고서에서 P0로 상향 조정했습니다.

## P1 — 중요하지만 긴급하지 않음 (5건)

### 2. 홈 히어로의 한 줄 소개가 슬로건 위주라 제품 카테고리가 늦게 드러남
- **페이지**: `/` (홈, hero 섹션)
- **근거**: H1은 "경력이라고 생각하지 않았던 경험에서 다음 가능성을 발견하세요."로 행동 유도형 슬로건이지 제품 설명이 아닙니다. 실제 작동 설명은 그 아래 lead 문단(본문 크기 텍스트)에 있고, 명확한 카테고리 명("Solar 기반 AI 진로상담 지원 프로토타입")은 페이지 맨 아래 footer에만 등장합니다(curl로 6회 반복 확인, 전 페이지 공통 footer). 반면 `/about`의 lead는 "GapProof는 학적·전공 밖의 경험을 근거 있는 역량과 이번 주 행동으로 연결하는 Solar 기반 진로 탐색 데모입니다."로 카테고리를 분명히 말하는데, 정작 첫 방문 페이지인 홈 히어로에는 이 문장이 없습니다.
- **참고**: 카피 분석은 같은 H1을 정반대 각도에서 강점으로 평가했습니다 — "핵심 가치(인정받지 못한 경험 → 가능성 발견)를 구체적으로 전달한다"는 것입니다. 두 평가는 모순이 아니라 서로 다른 층위를 가리킵니다. 헤드라인 자체의 문장력(카피 품질)은 이미 좋지만, 그 문장만으로는 "이것이 AI 분석 도구인지, 상담 서비스인지, 콘텐츠 페이지인지"라는 카테고리 신호(포지셔닝 품질)가 없다는 뜻입니다.
- **영향**: 짧은 시간에 여러 프로젝트를 훑어보는 심사자·신규 방문자가 헤드라인과 첫 화면만 보고 스크롤을 멈추면 제품 범주가 구분되지 않습니다. 카테고리 인지가 늦어질수록 이후 설명(역량 후보, 증거카드, 격차 등 자체 용어)을 맥락 없이 읽게 되어 이해 속도가 떨어집니다. "처음 방문한 사용자가 서비스 목적을 바로 이해하는지"라는 목표에 직접 해당하지만, 완전히 이해를 막는 수준은 아니고(본문 lead에 곧 설명이 나옴) 지연시키는 정도입니다.
- **수정 방향**: 홈 히어로의 eyebrow 또는 H1 바로 아래에 `/about`에 이미 있는 것과 같은 카테고리 문장(예: "Solar 기반 AI 경험 분석 데모")을 짧게 배치해, footer까지 스크롤하지 않아도 첫 화면에서 제품 범주가 확정되도록 합니다.
- **발견 관점**: 포지셔닝(product-marketing)

### 3. 가장 직관적인 경쟁 대안("ChatGPT에 직접 물어보기") 대비 차별화가 명시적으로 설명되지 않음
- **페이지**: `/about`, `/who`
- **근거**: `/about`의 유일한 경쟁 비교 섹션 "기존 서비스와 무엇이 다른가요?"는 "강의를 추천하는 데서 시작하지 않습니다"라는 문장으로 시작하는데, 이는 과제에서 언급된 세 경쟁군(자기소개서 첨삭, 일반 진로상담, ChatGPT 직접 질문) 중 어느 것과도 일치하지 않는 대상(강의 추천 서비스)과의 비교입니다. 코드 전체 grep 결과 "자기소개서", "첨삭" 단어는 어떤 page.tsx에도 등장하지 않습니다. ChatGPT는 `/who`의 "AI와의 대화에 경험이 쌓여 있는 분" 항목에서만 언급되는데, 여기서도 경쟁자가 아니라 "기존 대화 내용을 붙여넣는 입력 소스"로만 다뤄집니다.
- **영향**: GapProof의 핵심 동작(자유 텍스트 입력 → LLM이 역량 후보 제안)은 사용자가 ChatGPT에 직접 "이 경험에서 어떤 역량이 있을까?"라고 묻는 행동과 표면적으로 매우 유사합니다. "왜 이 전용 도구가 ChatGPT에 직접 묻는 것보다 나은가"에 대한 명시적 답이 없으면, 특히 기술을 아는 심사자일수록 이 질문을 스스로 던지게 되고 설득력이 떨어집니다. "핵심 가치 제안이 구체적인지"라는 목표를 직접적으로 약화시키는 문제입니다.
- **수정 방향**: `/about` 또는 `/why`에 "ChatGPT에 직접 물어보면 안 되나요?" 같은 명시적 질문을 세우고, 이미 갖춘 차별화 요소(원문 인용 근거 강제·환각 방지 검증, 확인 전 결과 미확정, 목표 직무 격차·이번 주 행동까지 구조화, 상담사 공유용 Gap Brief 출력)를 그 질문에 대한 답으로 재배치합니다. 자소서 첨삭·일반 진로상담과의 비교도 한 줄씩 추가하면 세 경쟁군 모두를 커버할 수 있습니다.
- **발견 관점**: 포지셔닝(product-marketing)

### 4. `/demo`가 자체 metadata를 갖지 못해 홈페이지 canonical·제목을 그대로 상속
- **페이지**: `/demo` (`app/demo/page.tsx`)
- **근거**: `app/demo/page.tsx`는 `"use client"`로 시작하며 `export const metadata`가 없고, `app/demo/layout.tsx`도 존재하지 않습니다. curl 결과 `<title>GapProof | 공백을 증거로</title>`(`app/layout.tsx` 기본값)와 `<link rel="canonical" href="https://gapproof.forblune.com/"/>`가 그대로 렌더링되어 `/demo` 자신이 아니라 홈페이지를 가리킵니다. 그런데 `/demo`는 `app/page.tsx`, `app/components/info-shell.tsx`, `app/components/mobile-drawer-nav.tsx` 등 홈페이지·모든 정보 페이지·모바일 내비에서 반복적으로 링크되는, 사이트 내 내부링크가 가장 많은 URL 중 하나입니다.
- **영향**: 현재는 canonical이 우연히 "/"를 가리켜 크롤러가 `/demo`를 별도로 색인하지 않을 가능성이 있지만, 이는 의도된 설계가 아니라 클라이언트 컴포넌트가 metadata를 못 가져 생긴 부수효과입니다. 이 프로젝트의 실제 목적인 "심사·멘토링 공유" 관점에서는, 데모 링크를 직접 공유했을 때 브라우저 탭 제목이 데모 내용과 무관한 홈페이지 문구로 보이는 즉각적 문제이기도 합니다. "SEO 메타데이터와 페이지 구조에 문제가 없는지"라는 목표에 직접 해당하며, 이 프로젝트의 주된 유통 경로(링크 공유)에 영향을 줍니다.
- **수정 방향**: `app/demo/layout.tsx`(서버 컴포넌트)를 추가해 `/demo` 전용 metadata(제목·설명, `alternates.canonical: "/demo"`)를 명시적으로 export하고, 검색 노출이 목적이 아니라면 `robots: { index: false, follow: true }`를 함께 지정해 의도를 우연이 아닌 명시적 설정으로 고정합니다.
- **발견 관점**: SEO

- **영향**: 실제 배포 도메인(gapproof.forblune.com)과 정확히 일치하지 않는 모든 환경(localhost 시연, Vercel 프리뷰 등)에서 동일한 콘솔 에러가 발생하며, Best Practices 점수를 100에서 96으로 깎는 유일한 원인입니다. SEO 카테고리 자체는 이미 100/100이라 색인·순위에는 영향이 없는 사실상 콘솔 위생 문제입니다.
- **수정 방향**: metadataBase가 manifest 링크까지 절대 URL로 만드는 현재 동작을 인지하고, 최종 심사/데모 환경의 실제 서빙 도메인이 metadataBase(gapproof.forblune.com)와 일치하는지 미리 확인합니다. 일치하지 않는 환경(로컬/프리뷰)에서 시연한다면 이 콘솔 에러가 Best Practices 96의 원인이라는 점만 감안하면 됩니다.
- **발견 관점**: SEO

### 15. 일부 정보 페이지 메타 설명이 SERP/미리보기 노출 가능 폭 대비 짧음
- **페이지**: `/guide`, `/how-it-works`, `/technology`, `/terms`, `/who`, `/about`
- **근거**: 문자 수 계산 결과 `/guide` 35자, `/technology` 41자, `/how-it-works` 42자, `/terms` 37자, `/about` 47자, `/who` 52자. 한글 스니펫 노출 가능 분량은 대략 70~90자 수준인데 이 페이지들은 절반 이하만 채우고 있습니다(홈페이지는 75자로 적절).
- **영향**: 글자 수 초과로 잘리는 문제는 없지만, 클릭을 유도할 수 있는 스니펫/미리보기 공간의 상당 부분을 비워두는 셈입니다. 실사용 검색 트래픽이 목표가 아니므로 시급성은 낮습니다.
- **수정 방향**: 각 페이지 description에 핵심 차별점이나 다음 행동을 유도하는 문구를 한 문장 더 추가해 70자 안팎까지 채웁니다.
- **발견 관점**: SEO

### 16. 타이틀 태그 브랜드 표기 순서 불일치 및 `/why` 제목 내 브랜드명 중복
- **페이지**: `/` (브랜드 먼저) vs 나머지 8개 페이지(브랜드 나중), 특히 `/why`
- **근거**: 홈페이지만 "GapProof | 경험을 증거로 바꾸는 진로 탐색"(브랜드가 앞)이고 나머지 8개는 전부 "OOO | GapProof"(브랜드가 뒤) 패턴입니다. `/why`는 "왜 GapProof인가 | GapProof"로 제목 문자열 안에 'GapProof'가 두 번 등장합니다.
- **영향**: 사소한 일관성 문제로 클릭률에 미치는 영향은 미미합니다. 브랜드 인지도 축적이 목적이 아닌 학사 데모 프로젝트 특성상 실질적 피해는 거의 없습니다.
- **수정 방향**: 전체 페이지에서 "브랜드 | 페이지명" 또는 "페이지명 | 브랜드" 중 하나로 표기 순서를 통일하고, `/why` 제목에서 중복되는 'GapProof' 표기를 정리합니다(예: "왜 GapProof인가").
- **발견 관점**: SEO

## 이번 감사가 다루지 않은 것

- **실제 검색 트래픽·전환율 데이터 없음**: 이 감사는 정적 코드·렌더링 결과·Lighthouse 측정치만을 근거로 하며, Google Search Console 노출·클릭·순위 데이터나 실사용자 전환율(퍼널 이탈률 등)은 확인하지 않았습니다. 프로젝트 특성상(심사·멘토링 공유용 학사 데모) 이런 데이터 자체가 존재하지 않을 가능성이 높습니다.
- **국제화(i18n) 해당 없음**: 모든 페이지가 한국어 단일 언어로만 존재하며, 다국어 지원이나 hreflang 관련 이슈는 이번 감사 범위에 포함되지 않았습니다.
- **코드 수정 없이 관찰만 수행**: 세 분석가와 이 통합 보고서 작성자 모두 코드베이스를 읽고 curl/Lighthouse/Playwright로 검증만 했을 뿐, 어떤 파일도 수정하지 않았습니다. 위에 제시된 수정 방향은 모두 제안이며 실제 적용 여부·구현은 별도 작업입니다.
- **A/B 테스트·정성 사용자 인터뷰 없음**: 헤드라인·CTA 문구에 대한 상대적 우열 판단(예: 항목 10의 CTA 강도 차이)은 카피라이팅 원칙과 분석가의 정성적 판단에 근거한 것이며, 실제 사용자 클릭률 비교 데이터로 검증되지 않았습니다.
- **비공개/게이트 뒤 데모 전 구간 전수 조사 아님**: STEP0~4는 `?sample=1` 샘플 데이터 경로로만 확인했으며, 실제 Solar API 연동 상태에서의 실시간 응답 문구(에러 메시지, 로딩 상태 카피 등)는 이번 감사 범위 밖입니다.
