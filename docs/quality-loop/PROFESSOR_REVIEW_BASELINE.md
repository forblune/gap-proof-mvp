## 근거 요약 (항목별)

### 1. 교수님 피드백 반영 (15.3/30)
- 🟢 **강점**: `/why`("GapProof가 하지 않는 것"), `/technology`("알려진 제한사항"), `/how-it-works`(폴백 동작 공개) — 과장 없는 정직한 문체가 일관됨. 교수님 원본 피드백의 신뢰 관련 질문("직업 가설 표시가 신뢰를 주나요, 자신감 없어 보이나요?")에 이미 잘 응답하고 있음.
- 🔴 **약점**: "화면 완성도"(screen polish) 절반은 미해결 — `<main>` 전체 배경 전환 0회, 홈의 "가상 사례" 카드 6개 라벨 무차별화(REFERENCE_STYLE_ANALYSIS.md에서 "필수" 표시), 정보 페이지들의 아이콘 없는 텍스트 벽 — 이는 교수님이 지적한 "이모지·시각요소 제거 후 텍스트 중심이 됨" 문제와 정확히 일치.

### 2. 첫인상과 시각적 위계 (9.7/20)

## 교수님이 가장 먼저 지적할 가능성이 높은 문제 5개

1. **정보 페이지의 텍스트 벽** — `/how-it-works` 12단계, `/technology` 보안 6블록, `/why` 7블록이 전부 아이콘 없는 볼드라벨+문단 나열. 교수님이 지적한 "이모지·시각요소 제거 후 밋밋해짐"과 정확히 일치하는, 가장 직접적이고 반복적으로 확인된 문제.
2. **홈페이지 섹션 배경 전환 0회** — 히어로부터 푸터까지 크림톤 단일 배경(computed style로 확인). 3개 참고 사이트 모두 최소 1회 이상의 명암 대비를 사용하는 것과 대비됨.
3. **밀도 높은 카드의 무차별 라벨** — 홈 "가상 사례" 카드 6개 라벨, 데모 STEP2 카드 9개 필드가 크기·굵기·색이 동일 — 참고 사이트들의 "제목→설명→메타" 3단 구분과 대비되며, 정확히 "직업 가설이 신뢰를 주는가"라는 교수님의 질문과 직결.
4. **H1/H2 weight 400 + 세리프/모노스페이스/산세리프 3종 혼용** — 참고 사이트 대비 첫인상이 약하고, 의도적이라기보다 우연처럼 보일 위험.
5. **실측 가능한 두 가지 구체적 결함** — fine-print 대비 4.49:1(WCAG AA 미달), `/technology` 표의 모바일 숨은 가로 스크롤. "화면 완성도"를 중시하는 심사자가 바로 찾아낼 만한 디테일.

## 유지해야 할 현재 장점 (변경 금지 대상 아님, 오히려 확장 대상)

1. **정직한 한계 고지 문체** — `/why`·`/technology`·`/how-it-works`의 과장 없는 존댓말. 시각적 개선 과정에서 절대 희석하지 말 것.
2. **`/demo` STEP2-3의 색상 코드 상태 배지 시스템** — 근거 확인 필요(코랄 #D9604C), 확인됨(티얼 #1F705F), 과장 주의(적갈 #A33A2A) 등 이미 프로덕션 코드에 존재하는 진짜 신호 체계. 새로 만들지 말고 확장할 것.
3. **STEP4의 다크 네이비 "증거카드"** — 하이브리드 다크 섹션 방향의 내부 선례. 히어로/CTA/푸터로 일반화하는 근거로 사용.
4. **시맨틱 HTML** — `dl/dt/dd`, `blockquote`, `ul/li` 기반. 아이콘·위계 개선은 마크업 재작성 없이 이 구조 위에 추가(additive)로만 진행.
5. **가로 오버플로 0건** (전 페이지·전 브레이크포인트) — 반드시 회귀 없이 유지.
6. **티얼 액센트(rgb(31,112,95)) 일관 재사용**(eyebrow·case-tag) 및 이미 참고 사이트 패턴과 부합하는 CTA 스타일 — 새 액센트 색을 도입하지 말고 이 색을 확장.
7. **`/guide`의 이미 표 형태인 5단계 번호 구조** — `/how-it-works`의 평문 나열보다 우수한, 이미 사내에 존재하는 패턴. 새로 발명하지 말고 재사용.
