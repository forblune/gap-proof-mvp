## 1. 이번 MVP가 증명할 한 가지

> Solar가 한국어 비정형 경험을 ‘역량 + 원문 근거 + 빠진 정보’로 구조화하고, 사용자가 이를 확인하면 목표직무의 격차와 실행 가능한 다음 행동으로 연결할 수 있는가?

공식 학점 인정, 전국 직무 추천, 기관 데이터 연동을 증명하려 하지 않는다. **증거가 생기는 순간**과 **상담이 다음 행동으로 전환되는 순간**을 보여주는 것이 MVP의 목적이다.

## 2. 사용자와 도입기관 가설

### 개인 사용자

- 최근 쉬었거나 진로를 전환 중이다.
- 전공 밖의 독학·강의·프로젝트·아르바이트 경험이 있다.
- 무엇을 할 수 있는지 설명하거나 다음 공부를 고르는 데 어려움이 있다.

### 운영 사용자

- 청년 일자리센터 또는 진로상담기관의 상담사다.
- 첫 상담 전에 내담자의 흩어진 경험과 목표를 정리할 시간이 부족하다.
- AI의 최종판정이 아니라 근거가 연결된 상담 보조자료를 원한다.

### 대표 데모 페르소나

- 항공물류 전공
- AI 수학·웹·아두이노 독학
- Solar 기반 상담 프로토타입 제작 경험
- 목표직무: AI 서비스 기획자
- 강점 후보: 문제발견, 도메인 연결, AI API 프로토타이핑
- 격차 후보: 사용자 검증, 데이터 지표, 기관 개인정보 설계

## 3. 5개 핵심 화면

### S1. 시작·동의

- 서비스가 진로를 판정하지 않는다는 안내
- 원문 저장 여부와 비식별 통계 공유를 각각 선택
- 샘플로 체험하기 버튼

**완료조건:** 동의 선택 전에는 경험을 서버에 전송하지 않는다.

### S2. 경험함

- 경험 텍스트 입력
- 출처 유형: 프로젝트 / 강의·수료 / 일·아르바이트 / 학교 / 기타
- 선택적 링크
- 예시 3개로 빠른 입력

**완료조건:** 한 문장만으로도 제출할 수 있고, 민감정보 경고를 확인할 수 있다.

### S3. 역량 확인

- Solar가 제안한 역량명
- 반드시 함께 보이는 원문 근거 문장
- 신뢰도는 숫자 대신 높음/확인 필요로 표시
- 빠진 정보와 추가질문
- 확인 / 수정 / 거절
- 증거등급 0~3과 산정 이유

**완료조건:** 근거가 없거나 사용자가 확인하지 않은 항목은 다음 단계에 포함되지 않는다.

### S4. 격차 지도·다음 행동

- 목표직무는 MVP에서 AI 서비스 기획자 1개
- 확인된 강점 3개 이내
- 우선 격차 3개 이내
- 행동 3개: 학습 / 미니프로젝트 / 상담
- 각 행동에 예상시간과 완료조건

**완료조건:** 사용자가 이번 주 행동 하나를 선택하고 선택 이유를 한 줄 남긴다.

### S5. GapProof 카드·상담용 Gap Brief

- 개인 카드: 목표, 확인된 역량, 증거등급, 핵심 근거, 다음 행동
- 상담 요약: 상담 질문 3개, 우선 격차, 선택 행동, 확인 필요 항목
- 수정·삭제·공유 철회
- PDF는 선택기능

**완료조건:** 개인 카드와 상담 요약의 역량 표현·등급이 서로 일치한다.

> 학습확인은 S4에서 여는 모달 또는 하위 화면으로 구현한다. 화면 수를 늘리지 않는다.

## 4. 증거등급

| 등급 | 이름 | 최소조건 | 카드 표현 |
|---|---|---|---|
| 0 | 자기기록 | 사용자가 서술했으나 연결자료·평가 없음 | 기록됨 |
| 1 | 연결증거 | 노트·링크·수료·산출물 중 하나와 원문 근거 | 근거 연결 |
| 2 | 수행확인 | 퀴즈·미니과제·프로젝트 완료조건 통과 | 수행 확인 |
| 3 | 기관확인 | 학교·교육기관·상담사 등 지정 주체가 확인 | 기관 확인 |

규칙:

1. Solar는 역량 후보를 제안할 수 있지만 등급을 임의로 올릴 수 없다.
2. 사용자 확인과 원문 근거가 없으면 공개 카드에 넣지 않는다.
3. 같은 역량의 증거가 여러 개면 가장 높은 등급과 모든 근거 링크를 보존한다.
4. 등급이 바뀌면 변경 전·후·근거·시각을 감사기록에 남긴다.

## 5. Solar 입출력 계약

### 서버 입력

```json
{
  "experience": "Solar API를 연결해 한국어 상담 MVP를 만들었다."
}
```

### 반드시 지켜야 할 구조화 출력

```json
{
  "source": "solar",
  "model": "solar-pro3",
  "claims": [
    {
      "id": 1,
      "skill": "AI API 기반 서비스 프로토타이핑",
      "quote": "Solar API를 연결해 한국어 상담 MVP를 만들었다.",
      "source": "사용자 입력",
      "tier": 0,
      "confidence": "확인 필요",
      "question": "직접 구현한 부분과 작동 링크를 추가할 수 있나요?",
      "status": "pending"
    }
  ],
  "notice": "Solar가 만든 후보입니다. 사용자가 확인하기 전에는 증명으로 사용하지 않습니다."
}
```

### 프롬프트 원칙

- 입력에 없는 경력·성과·숙련도를 만들지 않는다.
- `evidenceQuote`는 입력 원문의 연속된 문장 또는 구절이어야 한다.
- 역량은 채용확률이나 성격평가가 아니라 관찰 가능한 행동으로 표현한다.
- 근거가 부족하면 빈 배열과 구체적인 추가질문을 반환한다.
- 민감정보가 있으면 먼저 경고하고 해당 부분을 역량 근거로 사용하지 않는다.
- 결과는 한국어와 지정된 JSON 스키마만 반환한다.

### 서버 검증

1. 입력길이 20~3,000자 제한
2. JSON 객체와 필수 문자열 필드 정규화
3. `quote`가 실제 입력에 연속 문자열로 포함되는지 확인
4. 중복 제거 후 항목 수 최대 3개 제한
5. 모델이 반환한 등급은 받지 않고 모든 텍스트 후보를 서버에서 Lv.0으로 설정
6. 키 없음·시간초과·API 오류·JSON 오류·원문 불일치 시 규칙 기반 샘플로 폴백
7. 오류 로그에 사용자 원문과 API 키를 남기지 않음

## 6. 대표 직무 역량표 v0

MVP에서는 AI 서비스 기획자 한 직무만 수동 큐레이션한다.

| 역량 | 필요수준(0~3) | 중요도(1~3) | 확인 방법 예시 |
|---|---:|---:|---|
| 사용자 문제 정의 | 3 | 3 | 인터뷰·문제정의 산출물 |
| AI 기능·한계 이해 | 2 | 3 | 기능 명세·위험 검토 |
| 프로토타이핑 | 2 | 3 | 작동 링크·코드·시연 |
| 데이터·성과지표 설계 | 2 | 3 | 이벤트·KPI 표 |
| 사용자 검증 | 3 | 3 | 테스트 기록·반영사항 |
| 협업·문서화 | 2 | 2 | README·회의·결정기록 |
| 개인정보·AI 안전 | 2 | 3 | 동의·삭제·가드레일 설계 |

`격차점수 = 중요도 × max(필요수준 - 현재수준, 0)`

동점이면 ① 2시간 안에 시작 가능 ② 무료 또는 저비용 ③ 증거등급을 올릴 수 있는 행동 순으로 우선한다.

## 7. 데이터 모델

```text
UserProfile 1 ── N EvidenceItem
EvidenceItem 1 ── N SkillClaim
SkillClaim N ── N EvidenceItem
TargetRole 1 ── N RoleCompetency
UserProfile 1 ── N GapItem
GapItem 1 ── N LearningAction
LearningAction 1 ── N AssessmentAttempt
UserProfile 1 ── N ProofCard
UserProfile 1 ── N CounselorBrief
UserProfile 1 ── N ConsentRecord
UserProfile 1 ── N AuditLog
```

최소 테이블:

- `profiles`: 목표직무와 표시명
- `consents`: 원문저장·집계공유·철회시각
- `evidence_items`: 원문, 출처, 링크, 삭제상태
- `skill_claims`: 역량, 근거구절, 신뢰도, 확인상태, 등급
- `role_competencies`: 직무역량, 필요수준, 중요도
- `gap_items`: 현재수준, 격차점수, 상태
- `actions`: 종류, 제목, 예상시간, 완료조건, 선택상태
- `assessment_attempts`: 문제, 답안, 결과, 시도번호
- `audit_logs`: 변경주체, 변경 전후, 시각

## 8. 시스템 구성

```text
브라우저
  ↓
Next.js 화면·서버 API
  ├─ Solar API: 역량 후보·원문 인용·추가질문 추출 [구현, 실제 키 미검증]
  ├─ 규칙 엔진: 원문일치·Lv.0·샘플 폴백 [구현]
  ├─ 화면 상태: 확인·거절·행동선정·카드 [구현]
  └─ Supabase: 사용자 동의·구조화 데이터·감사기록 [미구현]
```

- Solar API 키는 브라우저에 보내지 않는다.
- 실제 사용자 원문은 로그에 남기지 않는다.
- 데모 계정과 실사용 계정을 분리한다.
- 시연 폴백은 실제 AI 결과처럼 위장하지 않고 `데모 데이터` 배지를 표시한다.

## 9. API 초안

| 메서드·경로 | 역할 |
|---|---|
| `POST /api/analyze` | Solar 구조화 추출·검증·샘플 폴백 **[구현]** |
| `PATCH /api/claims/:id` | 확인·수정·거절 |
| `POST /api/gaps/compute` | 대표 직무 격차 계산 |
| `POST /api/actions/recommend` | 행동 3개 생성·선정 |
| `POST /api/assessments` | 학습확인 생성·채점 |
| `POST /api/cards` | GapProof 카드 생성 |
| `GET /api/briefs/:userId` | 상담사용 요약 조회 |
| `DELETE /api/users/:id/data` | 원문과 파생결과 삭제 |

## 12. 파일럿에서 물을 질문

### 청년 5명

1. 처음 30초 안에 이 서비스가 무엇을 해주는지 알았나요?
2. AI가 뽑은 역량 중 틀리거나 과장된 것은 무엇이었나요?
3. 원문 근거와 증거등급을 신뢰할 수 있었나요? 이유는 무엇인가요?
4. 추천 3개 중 실제로 이번 주에 할 행동은 있었나요?
5. 이 과정에서 가장 에너지가 줄어든 단계는 어디였나요?

### 상담사 2명

1. Gap Brief만 보고 첫 상담을 시작할 수 있나요?
2. 어떤 정보가 빠지거나 과도한가요?
3. AI 출력 중 상담사가 반드시 다시 확인해야 할 부분은 무엇인가요?
4. 센터가 파일럿으로 도입하려면 어떤 승인·보안·성과지표가 필요한가요?
5. 개인당 또는 기관당 어떤 과금 단위가 현실적인가요?
