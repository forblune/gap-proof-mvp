# ADR-0001: Professor Feedback RC에서 회원 시스템의 범위

- 날짜: 2026-07-25 · 상태: 채택 · 관련: #43(Gate 7) #44(Gate 8) #11 #13

## Context

RC 지시는 "전역 접근 코드 구조를 최종 구조로 사용하지 않는다"며 회원가입·이용량·초대 코드 전체 세트를 Gate 7로 요구하되, "일부만 구현한 회원 시스템 공개 금지"와 "구현 규모·법률 선행조건 감사 후 RC 포함 여부 명시 판정"을 함께 요구한다. 한편 운영 Supabase 반영·이메일 인프라·카카오 콘솔 변경·운영 배포는 전부 Hard Stop(사용자 승인 필요)이다.

## Decision

RC 산출물은 **"로컬 완전 세트(스키마·RLS·인증 흐름·이용량·초대 코드) 구현과 검증 + 운영 전환 계획서"** 까지로 하고, **RC 기간의 운영 데모 접근은 기존 게이트 코드 방식을 유지**한다. 운영 공개 전환(운영 Supabase·메일 발송·콘솔 등록·배포)은 RC 완료 후 사용자 승인 항목으로 분리한다.

## Alternatives

1. RC 내 운영 공개까지 완료 — 기각: 운영 Supabase 반영이 Hard Stop이라 자율 범위에서 불가능하며, /privacy·/terms 전문가 검토 전 실계정 수집은 위험
2. 회원 기능 전면 보류(설계도 안 함) — 기각: 지시가 로컬·migration·테스트까지 자율 진행을 명시적으로 허용·요구
3. 부분 공개(가입만, 탈퇴 없이) — 기각: 지시로 명시 금지

## Reason

법률 선행조건(처리방침·약관·14세·탈퇴)은 문서만이 아니라 실동작 일치가 필요하고, 전문가 검토는 외부 조건이다. "일부 공개 금지" 원칙과 Hard Stop 체계 아래에서 위 결정이 유일하게 모순 없는 경로다.

## Consequences

- Gate 7은 로컬 Supabase(migration 8테이블·RLS·해시 초대 코드·ledger)와 테스트, 게이트→회원 전환 설계 문서를 산출
- Gate 8 /privacy·/terms는 **현행 무저장 데모 기준**으로 작성하고, 회원 전환 시 개정 절차(동의 버전 기록)를 문서에 내장
- 교수님 데모는 데모 코드 방식 유지 — 홈·정보 페이지·샘플 체험은 무코드 공개(Gate 2)

## Revisit condition

사용자가 운영 Supabase 반영과 메일 인프라를 승인하는 시점, 또는 심사 요건이 실계정 가입을 요구하는 경우.
