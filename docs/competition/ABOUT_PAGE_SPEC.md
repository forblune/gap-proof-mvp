# About 페이지 확장 명세 (`feat/competition-about`)

**목적**: 운영 About 페이지(`app/about/page.tsx`)에 기획 의도·스토리텔링은 유지하면서, 기술 스택·시스템 구조 요약·트러블슈팅 하이라이트·향후 계획을 추가한다. 대회 심사자가 About 페이지만 봐도 "무엇을 어떻게 만들었는지"를 알 수 있게 하는 것이 목표.

## 기존 유지 섹션 (변경하지 않음)

- "만든 계기" — 개인 배경 스토리
- "기존 서비스와 무엇이 다른가요?" — 차별점
- "하지 않는 판단" — 비목표 명시
- "개인정보 원칙" — 기존 4개 항목 그대로

## 신규 추가 섹션 (기존 `info-section` 클래스·`InfoShell` 컴포넌트 재사용, `globals.css` 수정 없음)

### 1. "어떻게 작동하나요?" (작동 방식, 하지 않는 판단 섹션 앞에 삽입)

경험→Solar 후보+원문→규칙 검증→사용자 확인→격차→이번 주 행동→증거카드 흐름을 짧은 순서 목록으로. 이미 "기존 서비스와 무엇이 다른가요?" 섹션에 요약되어 있으므로 중복을 피하고, 여기서는 STEP0~5 6단계를 명시적으로 나열(현재 실제 순서 그대로 — STEP3/4 CONFLICT를 About 페이지에서 재배열하지 않는다, 코드가 아직 그 순서이기 때문).

### 2. "만든 기술" (기술 스택, 신규)

`docs/competition/REBOOT_AI_PRELIMINARY_MASTER.md` §5의 검증된 스택을 사용자 친화적으로 요약: Next.js/React 19, Cloudflare Workers 배포, Upstage Solar, Tailwind CSS. 과장 없이 "실제로 쓰는 것만" 나열(Drizzle·Supabase는 언급하지 않음 — 미사용이므로).

### 3. "겪은 문제와 해결" (트러블슈팅, 신규)

`docs/competition/TROUBLESHOOTING_CASES.md`의 사례 2(측정 서버 문제)를 짧게 1개만 요약 — 전체 5개를 다 넣지 않고, 가장 흥미롭고 이해하기 쉬운 1건만(성능 문제인 줄 알았는데 측정 도구 문제였다는 이야기가 일반 방문자에게도 흥미로울 수 있음). 전체 사례는 별도 기술 문서 링크로 안내(단, 그 문서는 저장소 내부 문서라 공개 링크가 없으므로 "자세한 개발 기록은 개발일지에 남겨두었습니다" 정도로만 언급하고 실제 하이퍼링크는 걸지 않는다 — 존재하지 않는 공개 URL을 링크로 걸지 않기 위함).

### 4. "지금의 한계와 다음 계획" (향후 계획, 신규 — 시각적으로 "구현됨"과 "예정" 구분)

- "구현됨" 리스트(체크 아이콘 느낌의 `<ul>`): 원문 검증, 사용자 확인 필수, 격차·행동 연결, 증거카드·Gap Brief
- "다음에 할 일" 리스트(별도 `<ul>`, 다른 스타일 클래스 또는 소제목으로 구분): 증거등급 계산 정교화, 화면 순서 조정, 실제 산출물 기반 증거 경로 — `docs/planning/GAPPROOF_ALIGNMENT_AUDIT_2026-07-28.md`에서 가져온 정직한 항목
- 구현됨 항목에 없는 것을 있다고 쓰지 않는다(핵심 원칙)

## 시각적 구분 방법

기존 디자인 시스템에 별도 "구현됨/예정" 배지 컴포넌트가 없으므로, 새 CSS 클래스를 추가하지 않고 다음 방법으로 텍스트만으로 구분한다(요구사항: "불필요한 globals.css 수정 금지"):
- 소제목 텍스트 자체에 "지금 되는 것" / "다음에 할 일"처럼 명확한 한국어 구분자 사용
- 예정 항목은 문장 끝에 "(예정)"을 명시적으로 붙임
- 별도 아이콘이나 색상 배지는 추가하지 않음 — 기존 `<ul><li>` 패턴과 `<b>` 강조만 사용(기존 페이지들의 패턴과 일치)

## PR #78과의 충돌 최소화

PR #78은 `app/globals.css`(1개 opacity 값), `app/demo/layout.tsx`(신규), `tests/e2e/accessibility.spec.ts`를 건드린다. 이 About 페이지 작업은:
- `app/globals.css` 수정하지 않음
- `app/demo/` 디렉터리 건드리지 않음
- `tests/e2e/accessibility.spec.ts`의 기존 `PATHS` 배열은 건드리지 않되(PR #78이 그 파일을 수정 중이므로 충돌 방지), 필요한 접근성 검증은 별도 임시 확인(수동 axe 또는 새 파일)으로 대체하거나, 기존 `PATHS`에 `/about`이 없다면 그대로 두고 수동 검증만 수행

## 검증 대상

- 모바일 320/375/430px, 데스크톱 1440px에서 가로 스크롤/겹침 없음
- 기존 `tests/e2e/responsive.spec.ts`가 `/about`을 이미 커버하는지 확인 후, 커버하지 않으면 수동 확인으로 대체(파일 수정은 최소화)
- 링크 정상(존재하지 않는 외부 URL로 링크 걸지 않음)
- 카피가 `docs/planning/` 감사 문서의 CONFLICT와 충돌하지 않는지(예: "AI가 자동으로 확정합니다" 같은 표현 금지)
