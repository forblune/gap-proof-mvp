**상태**: 착수 전. 기능 구현이 완료 조건을 통과한 뒤 별도 단계로 진행한다.
여기 적힌 변경은 아직 하나도 적용하지 않았다.

## 왜 하는가

교수·사용자에게서 "가독성이 떨어진다"는 피드백을 반복해서 받았다. 색을 예쁘게 바꾸는 작업이 아니라,
정보를 더 쉽게 읽고 다음 행동을 빠르게 파악하도록 시각적 위계를 다시 세우는 작업이다.

## 기능 작업 중 실제로 발견한 것 (근거 있음)

1. **12px 본문이 57곳** — `grep -oE "font-size: 1[012]px" app/globals.css | wc -l` 기준.
   보조 문구가 지나치게 작고 흐리다. 이번에 주요 읽기 면 11곳만 13~15px로 올렸고 나머지는 그대로다.
2. **노란 밑줄 강조** — 형광펜처럼 보여 전문성을 약하게 만드는지, 강조할 가치가 있는 문장에만 쓰였는지 미검토.
   색만 바꾸지 말고 "이 문장을 정말 강조해야 하는가"부터 판단할 것.
3. **한 화면에 경쟁하는 강조** — STEP4는 역할 선택 · 확인된 역량 · 격차 3건 · 행동 3건 · 학습확인 패널 ·
   증거 충족도가 한 화면에 함께 있다(390px에서 약 2,700px 스크롤). 주요 행동 하나가 먼저 보이지 않는다.
4. **하드코딩 색상** — `app/globals.css`에 역할 기반 토큰과 직접 hex가 섞여 있다.
   `--color-danger`, `--color-danger-soft` 등은 fallback 값을 인라인으로 갖고 있어 정의가 분산돼 있다.
5. **인증·피드백 화면이 기존 토큰을 재사용하되 자체 값도 일부 도입** — 통합 시 함께 정리할 것.
6. **포커스 링 두께 불일치** — 전역은 3px, 인증 입력은 2px.
7. **모바일 헤더에 테마 전환 버튼이 없음** — `app/globals.css`의 `.info-nav { display: none }`(≤720px)로 숨겨지고
   햄버거 안에만 있다. 다크 테마가 적용돼 있다는 사실과 "직접 바꿀 UI가 없다"는 문제는 별개다.

## 진행 방식 (착수 시)

1. 주요 화면 실제 감사 → 2. 팔레트 3안(신뢰형/미래형/성장형)을 **시안으로** 비교 → 3. 근거와 함께 선택 →
4. 역할 기반 토큰으로 통합 → 5. 가독성 항목 동시 검토 → 6. 대비·색각·흑백·키보드·반응형 검증 →
7. 리뷰어 3인 항목별 85점 이상.

상태색과 보안·접근성 정책색은 브랜드색으로 덮지 않는다.
