## 2. 문제 정의

경력 공백·전공 불일치가 있는 청년은 "무엇이 부족한가"보다 "내가 가진 것이 무엇인지"를 정리하지 못해 멈춘다. 기존 도구는 적성·합격 가능성을 **판정**하려 들고, 그 판정에는 근거가 없다.

## 3. 목표 사용자

- 1차: 전공→직무 전환을 고민하는 20대(예: 항공물류 전공 → AI 서비스 기획)
- 2차: 진로상담사·기관(대학 취업지원팀, 청년센터) — Gap Brief로 상담 시간 절약

## 4. 핵심 가치

1. **증거 우선**: 원문 인용 없는 역량 주장은 채택하지 않음 [구현됨]
2. **사용자 확정**: AI 제안은 초안, 확정은 사용자(확인 0개 시 진행 차단) [구현됨]
3. **판정 금지**: 취업 가능성·적성 점수를 만들지 않음(상시 고지) [구현됨]
4. **정직한 상태**: 샘플/실연결 구분, 오류·한도 그대로 표기 [구현됨]

### 5.1 단계별 통과 조건 [구현됨]

| 단계 | 통과 조건 | 통과 못 할 때 |
|---|---|---|
| STEP1 → STEP2 | 경험 20자 이상 · 10,000자 이하 | 글자 수 안내(자동 절삭 없음) |
| STEP2 → STEP3 | **사용자가 확인한 역량 후보 1개 이상** | 진행 버튼 비활성 + "최소 1개를 확인해 주십시오" |
| STEP3 → STEP4 | 없음(건너뛸 수 있음) | — |
| STEP4 → STEP5 | **사용자가 확인한 증거 1개 이상**(학습확인 통과만으로는 불가) | 진행 버튼 비활성 + "다음 단계로 가려면 내 경험에서 확인할 수 있는 근거를 하나 이상 선택해 주십시오" |

증거가 0개면 어떤 경로로도 최종 결과(Proof Card)에 도달할 수 없습니다 — draft 복원 시점에도 확인 증거 0개인 STEP5 상태는 STEP4로 되돌립니다(`app/demo/page.tsx`).

## 6.1 인정 유형 — 무엇을 말해 주고, 무엇을 말해 주지 않는가 [구현됨]

코드: `app/lib/recognition.ts`의 `RECOGNITION_KINDS`. 한계(limits)가 비어 있는 인정 유형은 만들지 않습니다 — 한계 없는 인정은 과장이기 때문입니다.

| 인정 유형 | 말해 주는 것 | 말해 주지 않는 것 | 도달 가능 상한 |
|---|---|---|---|
| 학습 완료 | 학습 자료를 끝까지 봤다 | 이해했는지, 해 봤는지 | Lv.0 |
| 이해 확인 | 질문으로 되짚어 답할 수 있었다 | 실제로 해냈다는 뜻 아님 | Lv.0 |
| 실제 수행 | 실제 상황에서 직접 해 봤다(사용자 기록) | 결과물이 없으면 재확인 불가 | Lv.1 |
| 산출물 연결 | 결과물이 실제로 남아 있다 | 결과물의 품질은 평가 안 함 | Lv.2 |
| 외부 증빙 | 외부 기관 발급 문서가 있다 | GapProof가 진위를 검증하지 않음 | Lv.2 |
| 제3자 검토 | 지정 주체가 확인했다 | 이번 데모 범위 밖 | Lv.3 [계획] |

**상한은 "이 인정만으로 저절로 도달한다"는 뜻이 아닙니다.** 해당 역량에 사용자가 확인한 근거가
이미 있어야 하며(`maxTierFromRecord` 의 `hasConfirmedEvidence`), 그 위에서 넘지 못하는 천장을 뜻합니다.
산출물 링크만 있고 확인된 근거가 없으면 Lv.1 에 머무릅니다.

## 6.2 증거등급 상승 조건과 금지 조건 [구현됨]

코드: `app/lib/recognition.ts`의 `TIER_RULES`, 실제 계산은 `app/lib/engine.ts`의 `competencyStrength`/`hasConfirmedEvidenceFor`.

| 등급 | 오르는 조건 | **오를 수 없는 경우(금지)** |
|---|---|---|
| Lv.0 자기기록 | 사용자가 원문에서 확인한 역량 후보 | 사용자가 확인하지 않은 AI 제안 |
| Lv.1 근거 연결 | 그 역량에 확인 가능한 링크가 연결됨 | 링크 없이 설명만 덧붙이기 |
| Lv.2 수행 확인 | 그 역량에 확인된 근거가 이미 있고, 유효한 산출물 링크(http/https)가 연결됨 | **학습 완료로도, 이해 확인(퀴즈) 통과로도 오르지 않음. 이해 확인은 증거 강도 계산에 아예 반영되지 않음.** 수행 확인서 발급은 여기에 더해 수행 기록까지 요구하므로 등급보다 조건이 더 엄격함 |
| Lv.3 기관 확인 | 지정 주체가 확인 | 이번 데모에서는 어떤 경로로도 부여하지 않음 |

## 6.3 발급 문서 3종의 차이 [구현됨]

코드: `app/lib/recognition.ts`의 `CERTIFICATE_KINDS` + `canIssueLearningCertificate` / `canIssuePerformanceCertificate`.

| 문서 | 발급 조건 | 이 문서가 뜻하지 않는 것 |
|---|---|---|
| **학습 수료증** | 본인이 표시한 학습 자료 완료 + 필수 질문 전체 응답(문항당 10자 이상) | 실제로 수행했다는 뜻 아님. **증거등급을 올리지 않음**. GapProof는 시청 시간을 측정하지 않으므로 완료는 자기기록(Lv.0)입니다 |
| **수행 확인서** | 학습 수료 조건 + 유효한 산출물 링크(http/https) 1개 이상 + 사용자의 수행 기록 | 결과물의 품질을 GapProof가 평가·보증하지 않음 |
| **외부 증빙 기록** | 발급기관 · 발급일 · 문서번호 입력 | GapProof가 진위를 검증했다는 뜻 아님 [계획 — 입력 UI Phase 2] |

증서에 인쇄되는 "확인 범위" 문구는 발급 조건과 같은 모듈(`certificateScope`)에서 나옵니다 — 확인하지 않은 사실이 문서에 인쇄되지 않게 하기 위해서입니다. 조건을 충족하지 않으면 발급 버튼이 비활성화되고, 부족한 조건과 가장 작은 다음 행동을 화면에 그대로 보여 줍니다. 모든 발급 문서에는 발급 주체(`Forblune · GapProof`), 발급일, 고유번호, 확인 범위, **"공인 자격이 아니다"**는 고지가 함께 표시됩니다.

여기에 더해 **이 문서를 어디에 적어야 하고 어디에 적으면 안 되는지**를 문서가 직접 말합니다
(`CERTIFICATE_USAGE_NOTE`): 이력서·프로필의 교육·수료 또는 자격 항목에 적고, 경력·재직 항목에는
적지 않습니다. "공인 자격이 아니다"라는 고지만으로는 이 문서가 경력으로 둔갑하는 것을 막지 못하기
때문입니다. (조사 근거: `docs/planning/BENCHMARK_AUDIT.md`)

### 6.3.1 신뢰 구분은 라벨이 아니라 구조로 한다

인정 유형은 **확인 주체별로 다른 상자**에 담습니다(`RECOGNITION_GROUPS`).

| 그룹 | 담기는 인정 | 누가 확인했는가 |
|---|---|---|
| 내가 기록한 것 | 학습 완료 · 이해 확인 · 실제 수행 | 본인 표시·기록. GapProof가 사실 여부를 확인하지 않음 |
| 남아 있는 결과물 | 산출물 연결 | 누구나 링크로 재확인 가능. 품질은 평가하지 않음 |
| 외부 기관이 발급한 것 | 외부 증빙 · 제3자 검토 | 발급 주체가 GapProof가 아님 |

한 목록에 나란히 두고 라벨로만 구분하면 결국 같은 무게로 읽힙니다. 그룹이 없는 인정 유형은
만들지 않으며(`recognitionGroupOf`가 예외를 던집니다), 자기기록과 외부 발급은 겹칠 수 없습니다.

### 6.3.2 증거등급은 숙련도가 아니다

`Lv.0~3`은 **무엇이 확인됐는가**를 뜻하며 실력 점수가 아닙니다. 등급 숫자는 항상 확인된 사실과
함께 표시하고, 숙련도 레벨로 읽히는 표현(예: `achievedLevel` 류의 등급 표기)은 쓰지 않습니다.
발급기관의 루브릭 없이 숙련도를 표기하면 미검증 판정을 검증된 등급으로 오표시하게 됩니다.

### 6.3.3 직무 요건과 개인 근거를 하나의 점수로 합치지 않는다

목표 직무 비교는 **요건**과 **확인된 근거**를 서로 다른 단위의 두 열로 나란히 둡니다.
두 값을 하나의 적합도 점수로 합산해 **사용자에게 보여 주지** 않습니다 — 그 순간 직무 기술이 적성
판정으로 바뀝니다.

격차 목록의 정렬에는 내부 점수(`중요도 × 부족분`, `engine.ts`의 `computeGapMap`)를 씁니다. 이 값은
**어느 역량을 먼저 다룰지 순서를 정하는 용도**이며 화면에 수치로 내보내지 않습니다. 맨숫자로 노출하면
직무 요건과 개인 근거를 합친 값이 그 사람에 대한 점수로 읽히기 때문입니다.

사용자에게 보이는 **비율 수치**는 `증거 충족도`(요구 증거 중 확인 가능한 링크가 붙은 항목의 비율)뿐이며, 산정식과 "채용
가능성을 뜻하지 않는다"는 고지를 함께 표시합니다.

## 6.4 영상 학습(Gemini) [구현됨]

- 공개 YouTube URL → 요약·핵심 개념·타임스탬프·질문(기억/적용/성찰)·답안 가이드·추천 수행 과제·예상 산출물을 구조화 JSON으로 생성(`app/api/lesson/route.ts`).
- **API 키는 서버에서만 읽습니다**(`readServerEnv("GEMINI_API_KEY")`) — 클라이언트 번들에 포함되지 않습니다.
- 사용자가 요약을 직접 고치거나 다시 만들 수 있습니다.
- 잘못된 URL·비공개 영상·API 오류·시간 초과·빈 응답·깨진 JSON을 각각 다른 사용자 언어 메시지로 처리하며, 실패 시 자료를 지어내지 않습니다.
- **인정 상한**: 영상 학습과 질문 응답은 학습 완료·이해 확인까지만 인정되며, 그 자체로는 증거등급을 올리지 않습니다(`recognition.ts` 의 `LESSON_ONLY_MAX_TIER = 0`. 별도 분기로 집행하지 않고, 학습만 한 기록에 붙는 인정의 `maxTier` 가 모두 0 이라는 구조로 보장하며 테스트가 그 구조를 고정합니다).

## 12. 회원가입·로그인 계획 [계획 — 전부 미구현]

- 이메일 회원가입 + 이메일 인증(링크/코드) + 로그인 + 비밀번호 재설정
- 로그인 상태 유지(세션 연장)·이메일 기억하기(로컬) — **비밀번호 저장 금지**(브라우저 자동완성에 위임, 자체 저장 안 함)
- 소셜: 카카오·Google·Naver 로그인(최소 수집 원칙 — 프로필 사진 등 불요 항목 미요청, #11 구현 시 재검토)
- 가입 방식 안내(이메일 vs 소셜 차이), 동의 버전 기록, **만 14세 이상 확인**
- 회원 탈퇴·데이터 삭제(즉시 파기 원칙)
- 향후 PASS·휴대전화 본인확인 도입 검토(비용·필요성 평가 후)
- 인증 기반은 별도 private repo **forblune-auth-foundation**으로 분리 설계 예정(재사용 목적) — **아직 생성·구현되지 않음**
