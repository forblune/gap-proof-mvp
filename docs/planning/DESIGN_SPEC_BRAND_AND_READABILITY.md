- DNS·도메인·Worker 이름·Supabase 프로젝트·OAuth 외부 콘솔은 이번 작업에서 변경하지 않습니다.

## 2. 브랜드가 표현해야 할 의미

- 흩어진 경험을 모은다
- 경험에서 근거를 추출한다
- 부족한 근거를 확인한다
- 근거가 축적되고 다시 연결된다
- 과장된 인증이 아니라 정직한 증거 흐름을 만든다

`Gap` = 아직 정리되지 않은 경험과 근거 사이의 간격 ·
`Proof` = 사용자가 실제로 제공한 행동·결과물·외부 자료 ·
`GapProof` = 그 간격을 과장 없이 근거로 연결하는 과정.

**사용자의 결핍이나 부족함을 부정적으로 강조하지 않습니다.**

## 3. G 심벌

대문자 `G`를 핵심 심벌로 씁니다. G가 동시에 표현할 것:

- GapProof의 첫 글자
- 열린 원형 구조
- 끊어진 간격이 연결되는 모습
- 경험 → 근거 → 보완 → 기록의 순환
- 근거가 계속 축적되고 정리되는 과정

G의 열린 획 끝은 **작은 화살표 형태**로 설계하고, 화살표가 원을 따라 움직이며 순환하는 구조로 만듭니다.

**보이지 않아야 할 것**: 일반 새로고침 아이콘 · 동기화 아이콘 · 재활용 마크 ·
로딩 스피너 · 주식 상승 그래프 · 취업·성공 보장 화살표.

**필수 조건**: 정적 상태에서 16px favicon으로도 대문자 G로 식별될 것.
애니메이션 없이도 독립적인 브랜드 심벌로 완성될 것.

## 4. 키네틱 워드마크 모핑 애니메이션

단순 타이포그래피가 아니라 **키네틱 워드마크 기반 모핑 로고 애니메이션**으로 설계합니다.

흐름:

1. `Gap`과 `Proof`가 약간 떨어져 등장
2. Gap의 `a`, `p`가 G 방향으로 이동
3. a와 p의 획이나 형태가 G의 원형 구조에 합쳐짐
4. Proof의 글자 또는 작은 흔적이 G 쪽으로 흘러감
5. Proof가 소멸하기보다 **근거의 조각이 G 안에서 정리되는 느낌**
6. G의 열린 끝에서 화살표 구조가 드러남
7. G가 원을 따라 한 번 부드럽게 회전
8. `G 심벌 + GapProof 워드마크`로 정착

### 비교할 3안

| 안 | 방식 |
|---|---|
| A. Letter Merge | a와 p의 획이 G로 합쳐진다 |
| B. Evidence Flow | Proof의 작은 흔적이 G 내부로 흘러 들어간다 |
| C. Circular Trace | 전체 워드마크의 경로가 G의 순환 화살표로 정리된다 |

평가 기준: 브랜드 의미 전달 · 정적 로고 완성도 · 16px 식별성 · 모바일 성능 ·
과도한 장식 여부 · 새로고침·재활용 아이콘과의 혼동 · 사용자 독해 방해 여부.

가장 좋은 요소를 조합하되 복잡도를 높이지 않습니다.

### 모션 원칙

- 총 1.2~1.8초
- **첫 진입 시 한 번만** 재생, 무한 반복 금지
- CTA 사용을 막지 않음
- 로딩 화면·스피너로 사용하지 않음
- **CLS를 발생시키지 않음**
- 모바일에서는 움직임과 입자 수를 축소
- `prefers-reduced-motion`에서는 즉시 정적 로고 표시
- 애니메이션 실패 시에도 브랜드명과 기능이 정상 표시

## 5. 브랜드 컬러

방향: **Deep Indigo + Teal + Cool Neutral**

- Deep Indigo: 신뢰, 분석, 전문성, 안정
- Teal: 연결, 발견, 근거 축적과 다음 단계
- Cool Neutral: 긴 설명과 분석 결과의 가독성

### 사전 실측 (2026-07-28, 유사 팔레트 기준)

착수 전에 미리 재 본 결과, 아래가 기준 미달이었습니다. 실제 토큰으로 다시 측정해 반영합니다.

- `text-muted #768196` — background에서 3.72:1 (4.5 필요).
  같은 색상 계열에서 명도만 낮춘 `#656F81`이면 가장 어두운 배경(surface-muted)에서도 4.56:1.
- `border #D8DFE9` — surface에서 1.34:1. 정보를 전달하지 않는 **장식용 카드 테두리는 WCAG 1.4.11 대상이 아니므로 유지**하고,
  입력창·컨트롤 경계용 `border-strong`을 별도로 두어 3:1을 만족시킵니다.
- `disabled #A8B0BF` — 2.07:1. **비활성 컨트롤은 1.4.3/1.4.11 예외 대상**이므로 유지하되,
  비활성 상태를 색만으로 전달하지 않습니다.

### 사용 규칙

- 주요 CTA·링크: `brand-primary`
- G의 경로와 제한적 강조: `accent`
- 성공: `success` · 주의: `warning` · 오류: `error`
- **상태색을 브랜드색과 혼용하지 않습니다.**
- 색상값을 컴포넌트마다 하드코딩하지 않고 CSS 변수·공통 토큰으로 관리합니다.
  기존 중복 hex·rgb·임의 색상을 역할 기반 토큰으로 통합합니다.
- 색상만으로 의미를 전달하지 않고 텍스트·아이콘·형태를 함께 씁니다.
- 화면 대부분은 중립색, 브랜드색은 CTA와 핵심 흐름에 제한적으로 씁니다.
- 사용자의 퍼스널 컬러는 마지막 미세 조정의 참고 요소로만 씁니다.
  가독성·신뢰성보다 개인 취향을 앞세우지 않습니다.

## 6. 랜딩 노란색 밑줄

현재 `.hero h1 em::after`의 노란 밑줄(`--color-highlight #f4c84a`, 다크에서 불투명도 .22)을
**제거하거나 재설계**합니다. 노란색을 파랑으로 바꾸는 단순 교체는 하지 않습니다.

실제 화면에서 비교할 대안:

- G 화살표 곡률을 활용한 얇은 trace line
- 핵심 단어 하나 아래의 짧은 인디고·틸 선
- `brand-soft` 배경을 이용한 절제된 강조
- 애니메이션 없는 정적 강조

**한 화면에서 강조 효과는 한 곳만** 사용합니다.
형광펜처럼 넓은 밑줄, 본문을 가리는 효과, 계속 움직이는 장식은 금지합니다.

## 7. 가독성 감사 항목

색상과 로고만 바꾸고 끝내지 않습니다. 교수와 여러 사용자가 반복적으로 제기한 문제입니다.

- 제목·본문·보조문구 위계
- 글자 크기와 행간
- 문단 간격과 최대 줄 길이
- 낮은 텍스트 대비
- 카드·테두리·배지 과다
- 여러 CTA가 동시에 강조되는 문제
- 긴 설명과 반복 문구
- 모바일 줄바꿈과 여백
- 애니메이션이 독해를 방해하는 부분
- 기술 설명이 사용자 가치보다 먼저 나오는 부분

**한 화면에는 하나의 주요 행동만** 명확하게 강조합니다.

핵심 흐름이 쉽게 보여야 합니다: 경험 입력 → 근거 추출 → 부족한 근거 확인 → Proof Card 생성.

### 이미 확인된 가독성 결함 (직전 검토에서 나옴, 이 단계에서 처리)

- STEP3 한 화면에 60개 이상의 텍스트 블록이 쌓여 있음 (`app/demo/page.tsx`)
- 홈 상단에 `/demo`로 가는 동급 CTA 2개가 경쟁
- 노란색이 네 가지 의미로 쓰임: 장식 · 사용자 인용 테두리 · 샘플 모드 · 현재 단계
- `app/privacy/page.tsx`의 개정 이력이 한 블록에 4문장 통짜
