### 2.4 (#4) 확인된 증거만 격차·행동에 연결 — **CONFLICT**

> **상태 갱신(2026-07-28, 최소 갱신)**: `fix/evidence-grade-integrity` 브랜치(Draft PR, main 미병합)에서 STEP4→5 게이트를 `confirmedClaims.length === 0`만으로 단순화해 이 CONFLICT를 수정했다. 테스트·독립 리뷰 완료. 상세는 `docs/devlog/2026-07-28-evidence-grade-integrity.md` 참고. **아직 main에는 병합되지 않았다** — 이 문서의 나머지 서술(CONFLICT 판정 등)은 병합 전까지 유효한 것으로 유지한다.

- 기준 문서: 기준서 §7.3("확인된 역량이 0개면 격차 단계로 진행할 수 없다"), §1.4(결과물=확인된 증거+실행 약속).
- 코드 근거 `[코드 검증]`: `app/demo/page.tsx:1195` — STEP4→5("GapProof 만들기") 게이트가 `disabled={confirmedClaims.length === 0 && passedComps.length === 0}`. 즉 원문 인용으로 **확인된 증거가 0개**여도, 퀴즈만 통과(`passedComps`)하면 진행 가능하다. §6.6/§6.4 원칙(단순 퀴즈 통과가 "확인"을 대체할 수 없음)과 근본 원인이 #6(증거등급 CONFLICT)과 동일하다.
- 사용자/대회 위험: 원문 근거 없이도 "GapProof 결과"를 완주할 수 있어, 대회 심사 기준(§7.3의 핵심 신뢰 규칙)을 시연 중 직접 깨뜨릴 수 있음.
- 가장 작은 안전한 수정: STEP4→5 게이트를 `confirmedClaims.length === 0`(원문 확인 증거 기준)만으로 재정의하거나, 퀴즈 통과를 진행 조건에서 제외. #6의 수정과 함께 처리하면 별도 작업 아님.
- 필요한 테스트: `confirmedClaims=[]`, `passedComps=[X]` 조합에서 STEP5 진입 버튼이 비활성 상태로 남는지 확인하는 e2e 케이스 1개 추가.
- 예상 작업량: 소(약 1시간, #6과 동일 PR로 처리 권장).
- P0, 제출 전.

### 2.5 (#5) Learn Before Check가 강의 추천 서비스처럼 흐려지지 않는지 — **CONFLICT**

- 기준 문서: 기준서 §6.4 — "강의 추천은 GapProof의 시작이 아니라 확인된 격차를 닫는 행동 중 하나다... 이 순서를 지켜야 GapProof가 또 하나의 강의 추천 서비스로 흐려지지 않는다." §6.3 사용자 여정표(5단계: 시작→경험→역량확인→격차·행동→결과)에는 별도의 "학습 추천" 선행 단계가 없음.
- 코드 근거 `[코드 검증]`: `app/demo/page.tsx`의 실제 흐름은 STEP1(경험)→STEP2(역량확인)→**STEP3("먼저 알아보기", 오늘 PR #76로 신설)**→STEP4(격차·행동, gap-map 최초 노출)→STEP5(결과). STEP3의 추천 자료는 `lookIntoComp = gaps[0] ?? role.competencies[0]`(`page.tsx:339-342`)로 STEP4의 격차 계산과 **동일한 top-priority gap**에서 도출되지만, **사용자에게 격차가 아직 한 번도 보여지거나 확인되지 않은 시점**에 "먼저 알아보기"라는 이름으로 노출된다.
- 사용자/대회 위험: §6.4가 명시적으로 경고하는 실패 양상("또 하나의 강의 추천 서비스로 흐려짐")과 구조적으로 일치. 기준서를 먼저 읽은 심사자·멘토가 그 직후 실제 데모를 순서대로 클릭하면 이 불일치를 바로 인지할 가능성이 높음. Competition Presentation Reviewer도 독립적으로 "STEP3이 증거-확인-행동 3박자 시연 원칙을 시각적으로 압도할 위험이 가장 크다"고 확인.
- 가장 작은 안전한 수정(재구축 아님, 순서·카피만 변경): STEP3↔STEP4 순서를 맞바꾼다 — 격차 지도(현재 STEP4)가 새 STEP3이 되어 "확인된 격차"를 먼저 보여주고, "먼저 알아보기"(현재 STEP3)가 새 STEP4로 이동해 격차 확인 **이후** 행동 후보로 재배치된다. 데이터 배관(`gaps[0]`, `roleId` 공유)은 그대로 두고 단계 배열 순서, `moveTo()` 대상 두 곳, 표제 문구("먼저 알아보기" → "격차를 닫는 첫 행동 후보" 등 §6.4 표현에 맞춘 문구)만 바꾸면 된다. 7/31 기능동결 전에 반드시 반영.
- 필요한 테스트: 기존 `tests/e2e/learn-before-check.spec.ts`·`role-personalization.spec.ts`의 STEP 번호 어서션을 새 순서에 맞게 갱신(현재 189/189 통과 스위트가 순서 변경 시 그대로는 깨질 것이 확실하므로 회귀 방지용으로 우선 갱신 필요).
- 예상 작업량: 중(반나절 — 순서 변경 자체는 작지만 e2e 스펙 갱신과 리허설까지 포함).
- P0, 제출 전(7/31 기능동결 전).
- **주의**: 이 판정은 "조용히 해석"하지 않기 위해 CONFLICT로 명시한다. STEP3이 `gaps[0]`을 올바르게 재사용한다는 점에서 완전한 MISSING은 아니며, 순서 조정만으로 해결 가능한 정도의 CONFLICT임을 함께 기록한다.

### 2.6 (#6) 퀴즈·수료·수행·산출물과 증거등급의 관계 — **CONFLICT (최고 우선순위)**

> **상태 갱신(2026-07-28, 최소 갱신)**: `fix/evidence-grade-integrity` 브랜치(Draft PR, main 미병합)에서 `engine.ts`에 `hasConfirmedEvidenceFor()`를 추가해 퀴즈 통과가 이 역량에 매칭되는 확인 증거 없이는 Lv.3에 도달하지 않도록 수정했다. 리뷰 과정에서 STEP4/STEP5 화면 표시(`passedComps`)가 계산 로직과 별개로 동일 문제를 재현하고 있음을 추가로 발견해 함께 수정했다(`verifiedPassedComps` 분리). 단위 9개·E2E 21개(3브라우저)·독립 리뷰 4관점 전부 완료. 상세는 `docs/devlog/2026-07-28-evidence-grade-integrity.md` 참고. **아직 main에는 병합되지 않았다.**

- 기준 문서: 기준서 §6.4 — "단순 수강 완료가 아니라 수행 또는 산출물까지 연결돼야 증거등급이 오른다."
- 코드 근거 `[코드 검증]` (직접 확인, `app/lib/engine.ts:50-76`):

```
50 // 텍스트만 입력된 근거는 Lv.0(자기기록), 링크가 붙으면 Lv.1(근거 연결).
51 // 수행 확인(Lv.2)·기관 확인(Lv.3)은 MVP 범위 밖이므로 임의로 올리지 않는다.
...
56 // 학습확인(퀴즈)을 통과한 역량 id 집합. 통과 = 수행 확인(Lv.2) 증거.
...
74   if (passed[comp.id]) best = Math.max(best, 3); // 수행 확인(Lv.2)
```
