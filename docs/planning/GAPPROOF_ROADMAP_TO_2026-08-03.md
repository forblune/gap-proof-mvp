## submission-ready 정의

다음을 모두 만족할 때 제출 가능 상태로 간주한다:
1. 실제 Solar 연결 → 원문 근거 → 사용자 확인 흐름이 오류 없이 동작(자동화 테스트로 확인).
2. 확인된 증거만 격차·행동에 연결(증거등급 CONFLICT 수정 완료).
3. 격차 1개 이상 → 행동 1개 이상 → 증거카드 2종 + Gap Brief 생성까지 완주 가능.
4. 사용자 3명(또는 실패 시 명시된 축소 인원) 관찰 기록 + 관계자 1명 인터뷰 메모 존재.
5. 3분 시연이 대본과 실제 화면이 일치한 상태로 리허설 완료.
6. e2e + 단위 테스트 전체 통과, lint 신규 결함 0건.

## 실패 시 축소 범위 (fallback)

일정이 밀릴 경우 우선순위:
1. **반드시 유지**: 증거등급 CONFLICT 수정(#6) — 이것 없이는 제품의 핵심 신뢰 주장이 무너지므로 어떤 상황에서도 8/3 전 완료.
2. **가능하면 유지**: STEP3/4 순서 변경(#5), `&ldquo;` 수정(#14), 시연 대본 갱신(#10).
3. **미루어도 되는 것**: STEP4 정보 밀도 재설계(실측 결과가 미확정이면 그대로 진행), 18-34세 페르소나 명시적 표기.
4. **사용자 검증을 3명 못 채운 경우**: 발표 자료에 정직하게 "N명 검증, 나머지 미검증"으로 기록 — 과장 금지(기준서 원칙과 이 로드맵의 상위 지침).
