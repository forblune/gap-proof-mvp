# 벤치마킹 감사 — 유사 서비스가 잘 푼 문제와 GapProof 적용안

작성일: 2026-07-28 · 조사일: 2026-07-28 · 대상 브랜치: `feat/recognition-system`

이 문서는 **디자인을 복제하기 위한 것이 아닙니다.** 각 서비스가 어떤 사용자 문제를 어떤
정보 구조로 풀었는지만 봅니다. 브랜드 표현·색·레이아웃은 조사 대상에서 제외했습니다.

## 0. 조사 신뢰도 표기

증거 없는 문장을 쓰지 않기 위해 검증 수준을 항목마다 남깁니다.

| 대상 | 검증 수준 |
|---|---|
| Forage 인용 정책 | **원문 직접 검증** — 공식 PDF(Referencing Policy V5) 텍스트 추출 |
| LinkedIn 섹션·공개범위 | **원문 직접 검증** — 헬프센터 문서 |
| LinkedIn Licenses & certifications 필드 목록 | **미검증** — 원문 접근 실패(404), 2차 요약만 확보 |
| Teal 전 항목 | **미검증** — `tealhq.com` / `help.tealhq.com` 모두 HTTP 403 차단. 검색엔진 요약만 확보 |
| Open Badges 3.0 필드·검증 절차 | **원문 직접 검증** — 1EdTech 스펙 |
| Credly 반입 배지 처리 | **원문 직접 검증** — 지원 문서 |
| Europass 저장소 분리 | **원문 직접 검증** — 공식 안내 |
| O*NET Content Model·척도 | **원문 직접 검증** — O*NET Resource Center |
| NotebookLM 인용·YouTube 처리 | **원문 직접 검증** — Google 지원 문서 |
| NotebookLM 타임스탬프 인용 동작 | **미검증** — 공식 문서에서 확인되지 않음 |

미검증 항목은 아래 표에서 적용 제안의 근거로 쓰지 않았습니다.

## 1. 비교표

| GapProof 기능 영역 | 벤치마킹 서비스 | 그 서비스가 해결하는 문제 | 참고할 패턴 | 그대로 쓰면 안 되는 부분 | 현재 GapProof의 차이 | 적용 제안 | 기대 효과 | 위험도 | 난이도 | 우선순위 |
|---|---|---|---|---|---|---|---|---|---|---|
| 경험 입력 (STEP 1) | Teal | 완성된 문장을 먼저 요구해서 입력이 멈춘다 | 저장 단위(경험)와 표시 단위(문서)를 분리해 두고, 먼저 많이 쌓게 한 뒤 고르게 한다 | 누락 키워드에서 문장을 **자동 생성**하는 기능 — 사용자가 하지 않은 일을 제품이 만들어 낸다 | 현재는 자유 서술 한 칸. 조각 단위로 쌓는 구조가 없고, 한 번 쓴 경험을 다른 목적에 재사용하지 못한다 | 조각 입력(한 줄씩 추가) 허용. 저장된 조각은 그대로 두고 목표 직무별로 **선택 토글**만 한다 | 빈 화면 앞에서 멈추는 이탈 감소 | 낮음 | 중 | **P1** |
| 발급 문서 (수료증·수행 확인서) | Forage | 완료를 수행 성과로 오독한다 | 인증서가 "정해진 과제를 완료했다"만 주장하고, **어디에 적으면 안 되는지를 문서로 규정**한다(이력서의 Certifications에, Experience에는 금지) | `3~4배 채용` 같은 고용 성과 통계 | 우리 증서는 "공인 자격이 아니다"를 고지하지만, **잘못 쓰이는 자리를 막는 안내가 없다** | 증서 본문에 사용 위치 안내를 넣는다: 자격·수료 항목에 적고, 경력 항목에는 적지 않는다 | 증서가 경력으로 둔갑하는 오용을 문서 차원에서 차단 | 낮음 | 낮음 | **P0** |
| 학습 → 수행 흐름 | Forage | 배우기만 하고 해 보지 않는다 | 과제 제출 후 **모범답안 잠금 해제**(채점 없음) → 스스로 비교 | 모범답안 해제를 "검증"으로 포장하는 것. 제출만 하면 열리므로 평가가 아니다 | 우리는 이미 퀴즈 통과가 수행 인정을 주지 않는다. 다만 "비교해 볼 기준"이 없다 | 예상 산출물 예시를 제출 **후에만** 보여 주고, 본 사실이 어떤 인정도 만들지 않음을 명시 | 무엇을 만들어야 하는지 감을 주되 등급은 건드리지 않음 | 중 | 중 | P2 |
| Proof Card / 학습 기록 | LinkedIn | 상세 기록과 공유용 요약이 뒤섞인다 | **Projects(원장) ↔ Featured(요약 카드)** 2층 분리. 섹션 단위 공개 토글 | **Credential URL이 선택 항목** — 증거가 붙은 인증과 안 붙은 인증이 똑같이 보인다 | 우리는 한 화면에 상세와 요약이 섞여 있다. 공개 범위 선택은 Phase 2 | 상세 기록과 공유 카드를 분리하고, 증거 링크가 없으면 카드를 **시각적으로 격하**한다 | 공유 시 과장 위험 감소 | 중 | 중 | **P1** |
| 인정 유형 구분 | Credly · Europass | 자기신고가 발급 자격과 같은 신뢰도로 보인다 | **컨테이너 자체를 분리**한다. Credly는 반입 배지를 별도 "Other" 섹션에 두고 transcript에서 제외, Europass는 자기평가와 발급물을 다른 저장소에 둔다 | 검사 없이 봉인 아이콘·"Verified" 라벨만 재현하는 것 | 우리는 인정 유형 6종을 **한 목록**에 나열하고 라벨로 구분한다 | 자기기록 / AI 추출 후보 / 외부 자격을 **다른 영역**에 배치해 같은 목록에 못 들어가게 한다 | 규칙 위반을 라벨이 아니라 구조로 차단 | 중 | 중 | **P1** |

| 목표 직무 비교 | O*NET | 직무 요건과 개인 판정을 뒤섞는다 | 평정 대상이 **직업**이라 개인 점수를 낼 경로가 구조적으로 없다. | YouTube·Gemini 학습 | NotebookLM | 출처 없는 문장이 요약에 섞인다 | 인용 hover=전문, click=원문 위치 이동. 범위 밖 질문은 **아예 거절**. 실패 사유 4종을 명시(잘못된 링크·안전하지 않은 영상·캡션 없음·미지원 언어) | 퀴즈 점수·진도를 **역량 근거로 승격**시키는 것. 인용은 "소스에 있었다"만 보증하지 "사실이다·보유했다"를 보증하지 않는다 | 우리는 요약·개념·타임스탬프·질문을 생성하고 사용자가 편집·재생성할 수 있다. 실패 처리도 분기돼 있다 | 실패 사유 문구를 NotebookLM 수준으로 구체화(캡션 없음 등 원인별 안내) | 실패했을 때 다음 행동을 알 수 있음 | 낮음 | 낮음 | P2 |

## 2. 개선안 우선순위

### P0 — 오해·신뢰 훼손·증거 과장
1. **증서에 사용 위치 안내 추가**(Forage). "공인 자격이 아니다"만으로는 경력란에 적히는 것을 막지 못합니다.
2. **증거등급이 숙련도로 읽히지 않게 문구 고정**(Open Badges). 등급 옆에 확인된 사실을 항상 병기합니다.
3. **직무 요건과 개인 근거를 하나의 점수로 합치지 않는다**(O*NET) — 현행을 유지하되 문서에 원칙으로 못박습니다.

### P1 — 핵심 흐름 이해와 완료율
4. 경험 조각 입력과 목표별 선택 토글(Teal)
5. 상세 기록 ↔ 공유 카드 2층 분리, 증거 없는 카드 격하(LinkedIn)
6. 자기기록 / AI 추출 후보 / 외부 자격의 컨테이너 분리(Credly·Europass)

### P2 — 가독성·문구·시각 위계
7. 예상 산출물 예시를 제출 후에만 공개(Forage)
8. Gemini 실패 사유 세분화(NotebookLM)
9. `DESIGN_TODO_BRAND_READABILITY.md`의 잔여 항목

### P3 — 후속
10. 공개 검증 페이지·영구 발급 이력(Phase 2 유지)
11. O*NET 표준 taxonomy 연동 검토

## 3. 적용하지 않기로 한 것과 이유

| 적용하지 않음 | 이유 |
|---|---|
| Teal: 누락 키워드에서 문장 자동 생성 | 사용자가 하지 않은 일을 제품이 만들어 냅니다. GapProof 1번 원칙과 정면 충돌합니다 |
| Teal `6x faster` · Forage `3~4배` 성과 통계 | 고용 결과 예측입니다. 전면 금지 대상입니다 |
| LinkedIn: 증거 URL을 선택 항목으로 두기 | 증거 유무가 똑같이 보이게 됩니다 |
| LinkedIn: 발급 기관 로고 자동 부착 | 기관이 보증했다는 착시를 만듭니다 |
| Open Badges: `achievedLevel` 숙련도 표기 | 발급기관 루브릭이 없으면 미검증 판정을 검증된 등급으로 오표시합니다 |
| O*NET: 적합도 % 합산 | 직무 기술이 적성 판정으로 바뀝니다 |
| NotebookLM: 퀴즈 진도의 역량 승격 | 자가 학습 진도이지 평가가 아닙니다 |

## 4. GapProof가 이들과 다른 핵심 차별점

- **증거가 없으면 최종 결과를 만들지 않습니다.** 위 서비스 중 어느 곳도 산출물 생성을 증거 유무로 막지 않습니다.
- **AI가 제안하고 사용자가 확인한 것만 결과에 들어갑니다.** Teal은 AI 생성물을 그대로 문서에 넣습니다.
- **퀴즈 통과만으로는 어떤 증거등급도 오르지 않습니다.** 그 역량에 사용자가 확인한 증거가 이미 있을 때에만
  이해 확인이 등급 상승에 관여합니다(`engine.ts`의 `competencyStrength`). 확인된 증거가 0개면 퀴즈를 통과해도
  오르지 않습니다. 코드와 테스트로 강제합니다(`tests/recognition.test.mjs`).
- **사용자에게 보이는 숫자는 증거 충족도뿐이며 산정식과 "채용 가능성이 아니다"는 고지를 함께 표시합니다.**
  격차 정렬에 쓰는 내부 점수(`중요도 × 부족분`)는 순서를 정하는 데만 쓰고 화면에 수치로 내보내지 않습니다.
