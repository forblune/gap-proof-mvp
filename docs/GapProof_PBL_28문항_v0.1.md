# GapProof PBL 28문항 답안 v0.1

- 작성일: 2026-07-22 (2026-07-23 대회 공고 반영)
- 상태: 멘토링 전 가설 초안 — 공고(두 트랙·서면예선·현장PT) 기준으로 정합화
- 프로젝트 한 줄: **공백·전환 경험을 역량 증거로 바꾸는 Solar 기반 AI 진로상담 지원 플랫폼**
- 대회 대상 = 두 트랙: **트랙1 쉬었음·자립준비청년 / 트랙2 경력보유여성** — GapProof는 동일 엔진으로 두 트랙을 모두 지원
- 1차 데모 페르소나(트랙1): 쉬었음 청년 중 비전공·독학·단기교육·프로젝트 경험이 흩어진 사람
- 병행 대상(트랙2): 돌봄·경력중단 기간의 학습·활동 경험이 흩어진 경력보유여성
- 1차 도입기관 가설: 청년 일자리센터·진로상담기관 (트랙2 확장 시 여성새로일하기센터)
- MVP 대표 목표직무 가설: AI 서비스 기획자 (엔진은 다른 직무로 일반화 가능)
- 제출 트랙(1/2) 최종 선택: **멘토링에서 확정** → v0.2 반영

> 아래 28개 답안은 PBL 화면에 바로 옮길 수 있는 문장이다. 예선은 산출물 **서면평가**(8월 중순), 본선은 **현장 PT**(트랙별 10팀, 9월 초)이므로 문서만으로 이해되게 작성했다. 6·7단계의 구현 결과, 테스트 결과, 제출 링크는 아직 없는 결과를 꾸며 쓰지 않고 `미실행/미정`으로 표시했다. 멘토링에서 제출 트랙과 직무 범위를 확정한 뒤 v0.2로 갱신한다.

## 1단계. 문제 인식

### 1. 관찰하기

1. **쉬었음 청년 / 진로를 다시 정하려는 때 / 집에서 배운 AI·웹·아두이노, 단기교육, 아르바이트 경험은 있지만 이것이 어느 직무 역량인지 설명하기 어렵다.** 이력서를 열어도 학력과 자격증 칸만 보여 공백 동안의 시도는 사라진다.
2. **비전공 대학생 / 전공 밖의 온라인 강의를 수료한 뒤 / 수료증은 생기지만 핵심을 실제로 이해했는지, 다음에 무엇을 배워야 하는지 알기 어렵다.** 전과나 복수전공을 하지 않으면 배운 것을 학적 안에서 인정받기도 어렵다.
3. **청년상담사 / 첫 상담 30~50분 동안 / 내담자의 노트·링크·수료증·프로젝트가 흩어져 있어 역량을 확인하는 데 시간이 많이 든다.** 상담이 진로 행동 설계보다 과거 설명에 머무르기 쉽다.
4. **교육·일자리기관 담당자 / 다음 교육과정을 기획할 때 / 개인들이 어떤 역량에서 막히는지 익명화된 수요 데이터를 얻기 어렵다.** 기존 공급 과정과 담당자의 경험을 중심으로 프로그램을 편성하게 된다.

### 2. 불편함 수집 · 브레인스토밍

① 공백 중의 독학·프로젝트·생활 경험이 취업에서 쓸 수 있는 역량 증거로 번역되지 않는다.  
② 목표직무를 정하고 필요한 공부를 찾고 실행계획을 세우는 비용이 너무 커 중간에 포기한다.  
③ 온라인 수료 기록은 남지만 놓친 핵심 개념과 실제 숙련도는 확인하기 어렵다.  
④ 대학 학적은 정적이어서 전공 밖에서 새로 쌓은 역량과 빠르게 변하는 직무 요구를 반영하기 어렵다.  
⑤ 상담기관은 내담자의 자료 정리에 시간을 쓰고, 개인별 격차와 다음 행동을 한눈에 보기 어렵다.  
⑥ 국가는 어떤 청년에게 어떤 역량 지원이 필요한지 실시간·세부 단위의 익명 데이터를 얻기 어렵다.  
⑦ 기존 서비스는 진단, 강의 추천, 수료증, 상담기록이 분리돼 있어 학습이 실제 증거로 이어지지 않는다.

### 3. 문제 선정

평가 기준은 **빈도 / 절박성 / 기존 서비스의 공백 / 2주 MVP 가능성** 네 가지로 잡았다.

- ① 경험이 역량 증거로 번역되지 않음: ○ / ○ / ○ / ○
- ② 다음 학습경로 탐색 비용이 큼: ○ / ○ / △ / ○
- ③ 수료와 숙련의 차이: ○ / △ / △ / ○
- ④ 정적인 학적의 한계: ○ / ○ / ○ / △
- ⑤ 상담사의 자료정리 부담: ○ / ○ / ○ / ○
- ⑥ 국가 수요데이터 부족: △ / ○ / △ / ✕

**최종 선정 문제:** 비정형 경험이 확인 가능한 역량 증거로 바뀌지 않아, 개인은 자신의 다음 진로 행동을 정하기 어렵고 상담사는 그 연결을 매번 처음부터 만들어야 한다.

**선정 이유:** 청년과 상담기관 양쪽의 실제 불편을 동시에 다루며, Solar의 한국어 문맥 이해와 구조화 기능으로 핵심 가치를 짧은 기간 안에 시연할 수 있다. 국가 데이터와 학적 연계는 이 코어가 검증된 뒤 확장한다.

### 4. 문제 상황 기술

쉬었음 청년과 비전공 학습자는 진로 전환을 시도할 때 집·학교·온라인에서 만든 노트, 수료증, 프로젝트 링크, 아르바이트 경험을 가지고 있지만, 이것을 목표직무의 역량으로 번역하고 부족한 부분과 다음 학습을 정하려면 여러 사이트와 상담을 직접 오가야 한다. 상담기관도 첫 상담에서 자료를 다시 듣고 정리해야 한다.

**한 문장 요약:** 노동시장은 빠르게 변하지만 학적·자격은 정적이어서, 그 사이의 변화 비용을 개인과 상담사가 반복해서 부담하고 있다.

## 2단계. 문제 정의

### 1. 핵심 문제 한 문장 정의

**흩어진 비정형 경험 때문에 다음 진로 행동을 정하기 어려운 쉬었음 청년을 위해, Solar가 경험 속 역량과 근거 문장을 구조화하고 사용자가 확인한 증거만 목표직무 격차 및 3개의 학습 행동으로 연결하는 서비스를 만든다.**

### 2. 대상 사용자 · 목표

- **주 사용자(대회 두 트랙):** 트랙1 쉬었음·자립준비청년, 트랙2 경력보유여성 — 공백·전환기를 지나며 독학·활동·프로젝트 경험이 흩어진 사람. MVP 데모는 트랙1 페르소나로 진행하되 동일 엔진이 트랙2(돌봄·경력중단 경험의 역량화)에도 적용된다.
- **주 사용자의 목표:** 15분 안에 ‘내가 이미 가진 역량·그 근거·부족한 역량·이번 주 다음 행동’이 담긴 GapProof 카드를 만든다.
- **운영 사용자:** 청년 일자리센터·진로상담기관의 상담사
- **운영 사용자의 목표:** 상담 전에 1쪽 Gap Brief를 확인하고, 과거 설명보다 다음 행동 합의에 상담시간을 쓴다.
- **확장 사용자:** 대학 진로센터·학사부서, 여성새로일하기센터, 교육기관, K-MOOC 등
- **장기 목표:** 개인 동의와 비식별화를 전제로 반복되는 역량 격차를 집계해 교육과정 기획에 활용한다.

### 3. 성공 기준

1. 청년 파일럿 5명 중 4명 이상이 15분 안에 온보딩부터 다음 행동 선택까지 완료한다.
2. 5명 중 4명 이상이 원문 근거가 연결된 역량 1개 이상의 GapProof 카드를 만든다.
3. 상담사 2명 모두가 1쪽 Gap Brief의 상담 준비 유용성을 5점 중 4점 이상으로 평가한다.
4. 대표 시나리오가 연속 5회, 회당 3분 안에 중단 없이 작동한다.
5. 원문 근거가 없거나 사용자가 확인하지 않은 역량이 ‘검증됨’으로 표시되는 사례는 0건이어야 한다.
6. 사용자는 자신의 기록을 수정·삭제할 수 있고, 동의하지 않은 개인 원문은 기관 통계에 포함되지 않는다.

### 4. 범위 정하기 (포함 · 제외)

**이번 MVP에 포함**

1. 경험 텍스트·수료 정보·프로젝트 링크 입력
2. Solar의 한국어 역량 후보, 근거 문장, 신뢰도, 추가질문 구조화
3. 사용자 확인·수정과 증거등급 0~3 표시
4. 대표 목표직무 1개와의 역량 격차 지도
5. 다음 행동 3개 추천: 학습 1개, 미니프로젝트 1개, 상담 행동 1개
6. 놓친 핵심 개념 보충과 최대 3회 학습확인
7. 개인용 GapProof 카드와 상담사용 1쪽 Gap Brief
8. 최소한의 동의·삭제·감사기록

**이번 MVP에서 제외**

1. 공식 학점·학위·국가자격 인정
2. 대학 학적, Work24, K-MOOC, NCS의 실시간 API 연동
3. 전국 직업과 전 연령을 다루는 추천
4. 국가 단위 실시간 인력수요 대시보드
5. 기업 채용합격 예측과 개인의 진로를 단정하는 자동판정
6. 사용자 동의 없는 원문 공유

## 3단계. 문제 분해

### 1. 입력 · 처리 · 출력으로 나누기

**입력**

- 사용자 목표와 희망직무
- 경험 설명, 강의·수료 정보, 노트, 프로젝트 링크
- 사용자의 역량 후보 확인·수정·거절
- 학습확인 답안과 상담사 피드백

**처리**

- 불필요한 개인정보 최소화
- Solar로 경험에서 역량·근거·신뢰도·추가질문 추출
- 출력 형식 검증 후 사용자 확인
- 증거등급 계산
- 대표 직무 역량표와 비교해 격차 계산
- 격차의 중요도와 실행가능성을 기준으로 다음 행동 3개 선정
- 학습확인 결과에 따라 보충자료 또는 증거등급 갱신
- 개인용 카드와 상담용 요약 생성

**출력**

- 확인된 역량과 원문 근거
- 증거등급 0~3
- 목표직무 격차 지도
- 이번 주 다음 행동 3개
- GapProof 카드
- 상담사용 1쪽 Gap Brief
- 동의된 데이터만 반영한 익명 집계 항목

### 2. 하위 기능 목록화

① 온보딩·동의 관리  
② 경험 입력과 링크 등록  
③ 개인정보 최소화·텍스트 전처리  
④ Solar 역량 추출  
⑤ 구조화 출력 검증과 실패 복구  
⑥ 사용자 역량 확인·수정  
⑦ 증거등급 계산  
⑧ 목표직무 선택과 역량표 조회  
⑨ 역량 격차·우선순위 계산  
⑩ 학습·프로젝트·상담 행동 추천  
⑪ 핵심 개념 보충과 최대 3회 학습확인  
⑫ GapProof 카드 생성  
⑬ 상담사용 Gap Brief 생성  
⑭ 수정·삭제·감사기록  
⑮ 동의된 비식별 집계

### 3. 조각 간 연결 (데이터 흐름)

`동의 → 경험 원문 → 개인정보 최소화 → Solar 추출 → JSON 형식 검증 → 역량 후보·근거 → 사용자 확인 → 확정 역량·증거등급 → 목표직무 역량표와 비교 → 격차 목록 → 행동 3개 → 학습확인 → GapProof 카드 → 상담사 Gap Brief`

- Solar의 출력은 곧바로 확정 역량이 되지 않고 반드시 사용자 확인 단계를 지난다.
- 증거등급과 확인 상태는 추천과 카드 생성의 입력으로 사용된다.
- 학습확인 결과는 기존 기록을 지우지 않고 새 증거로 추가한다.
- 기관에는 개인 원문 대신 동의된 비식별 격차 항목만 전달한다.

### 4. 우선순위 · 난이도 표시

1. **핵심 / 중:** 경험 입력·대표 사용자 시나리오
2. **핵심 / 상:** Solar 구조화 추출과 형식 검증
3. **핵심 / 중:** 사용자 확인·수정과 증거등급
4. **핵심 / 중:** 대표 직무 1개의 역량표와 격차 계산
5. **핵심 / 중:** 다음 행동 3개 추천
6. **핵심 / 중:** GapProof 카드·Gap Brief 생성
7. **핵심 / 상:** 개인정보 동의·삭제·감사기록
8. **선택 / 중:** 최대 3회 학습확인과 보충 루프
9. **선택 / 하:** PDF 내보내기
10. **후속 / 상:** 기관 통계와 외부기관 연동

**제작 순서:** 1→2→3→4→5→6으로 핵심 데모를 먼저 완성하고, 7을 배포 전 필수로 닫은 뒤 8~9를 추가한다. 10은 파일럿 이후로 미룬다.

## 4단계. 추상화

### 1. 핵심 정보 추리기

**꼭 필요한 정보**

- 사용자가 직접 쓴 경험 원문과 출처 유형
- Solar가 제안한 역량명, 원문 근거 문장, 신뢰도, 빠진 정보, 추가질문
- 사용자의 확인·수정·거절 상태
- 증거등급과 등급 산정 이유
- 목표직무의 필수 역량, 중요도
- 현재 역량과 목표역량의 차이
- 추천 행동의 종류, 소요시간, 완료조건
- 학습확인 시도 횟수와 결과
- 동의 범위, 수정·삭제 기록

**버리거나 수집하지 않을 정보**

- 사용자 동의 없는 가족사와 민감정보
- MVP에서 쓰지 않는 전국 모든 직무의 데이터

### 3. 핵심 규칙 일반화

**모든 경우에 통하는 핵심 규칙:** 원문 근거가 있고 사용자가 확인한 역량만 현재 역량으로 인정한 뒤, `격차점수 = 목표 중요도 × (필요수준 - 현재수준)`으로 계산하고, 격차점수와 실행가능성이 높은 학습·프로젝트·상담 행동을 각각 1개씩 제시한다.

추가 안전 규칙은 다음과 같다.

- AI가 제안했다는 이유만으로 ‘검증됨’이 되지 않는다.
- 증거등급은 원문·링크·평가·기관확인보다 높게 표시할 수 없다.
- 사용자가 거절한 역량은 격차 계산과 카드에서 제외한다.
- 개인 원문은 동의 없이 기관 통계로 전달하지 않는다.

### 4. 반복 패턴 찾기

1. 각 경험마다 `입력 → Solar 추출 → 형식검증 → 사용자 확인`이 반복된다.
2. 각 역량마다 `근거 존재 확인 → 증거등급 계산 → 카드 표시 여부 결정`이 반복된다.
3. 각 목표역량마다 `현재수준 조회 → 격차점수 계산 → 행동 후보 생성`이 반복된다.
4. 각 학습확인마다 `문제 제시 → 채점 → 놓친 개념 안내 → 재시도`가 최대 3회 반복된다.
5. 사용자 수정 때마다 기존 값을 덮어 숨기지 않고 `변경 전 → 변경 후 → 시각` 감사기록을 남긴다.
6. 이 패턴을 함수로 만들면 목표직무나 기관이 바뀌어도 같은 흐름을 재사용할 수 있다.

## 5단계. 알고리즘 설계

### 1. 실행 순서 나열 (의사코드)

```text
1. 사용자에게 서비스 목적, AI 한계, 저장·공유 범위를 설명하고 동의를 받는다.
2. 사용자가 경험 원문과 선택적 링크를 등록한다.
3. 추천에 불필요한 개인정보를 표시하거나 제거한다.
4. 각 경험을 Solar에 구조화 출력 형식과 함께 보낸다.
5. Solar 응답이 정해진 JSON 형식인지 검사한다.
6. 역량 후보, 근거 문장, 신뢰도, 빠진 정보, 추가질문을 화면에 보여준다.
7. 사용자가 각 후보를 확인·수정·거절한다.
8. 확인된 항목에 출처와 평가 상태를 기준으로 증거등급 0~3을 부여한다.
9. 사용자가 대표 목표직무 1개를 고른다.
10. 확인된 역량과 목표직무 역량표를 비교한다.
11. 각 목표역량의 격차점수를 계산해 큰 순서로 정렬한다.
12. 상위 격차에 대해 학습 1개, 미니프로젝트 1개, 상담 행동 1개를 고른다.
13. 사용자가 이번 주 실행할 행동을 선택한다.
14. 학습 행동이면 핵심확인 문제를 내고 최대 3회 채점·보충한다.
15. 확인된 역량, 근거, 격차, 선택 행동으로 GapProof 카드를 만든다.
16. 개인 원문을 제외한 1쪽 상담사용 Gap Brief를 만든다.
17. 사용자가 수정·삭제를 요청하면 관련 데이터와 파생 결과를 함께 갱신한다.
```

### 2. 조건(분기) 정하기

- 만약 원문에서 해당 역량을 뒷받침하는 문장을 찾지 못했다면 역량 후보로 확정하지 않고 추가질문을 한다.
- 만약 Solar 신뢰도가 기준보다 낮다면 ‘확인 필요’로 표시하고 추천 계산에서 제외한다.
- 만약 응답 JSON 형식이 틀렸다면 한 번 자동 재요청하고, 다시 실패하면 수동입력 화면으로 전환한다.
- 만약 사용자가 역량을 수정하면 수정된 표현과 원문 근거가 맞는지 다시 확인한다.
- 만약 링크나 평가가 없다면 증거등급을 0 또는 1로 제한한다.
- 만약 현재수준이 필요수준 이상이면 그 역량은 부족역량 추천에서 제외한다.
- 만약 학습확인을 틀리면 놓친 개념과 짧은 보충자료를 보여준 뒤 남은 횟수 안에서 다시 문제를 낸다.
- 만약 3회 안에 기준을 충족하지 못하면 ‘추가 학습 필요’로 표시하고 증거등급을 올리지 않는다.
- 만약 사용자가 집계 공유에 동의하지 않으면 기관용 비식별 통계에서도 제외한다.
- 만약 Solar API가 시연 중 중단되면 미리 준비한 예시 응답을 ‘데모 데이터’라고 명시해 흐름만 시연한다.

### 3. 반복 정하기

- 등록된 **모든 경험**에 대해 역량 추출을 반복한다.
- 추출된 **모든 역량 후보**에 대해 사용자 확인과 증거등급 계산을 반복한다.
- 대표 직무의 **모든 필수역량**에 대해 현재수준과 격차점수 계산을 반복한다.
- 상위 격차의 **모든 행동 후보**에 대해 시간·비용·완료조건을 평가한다.
- 학습확인은 **최대 3회** 반복하며, 매회 같은 문제를 복사하지 않고 놓친 개념을 다시 확인한다.
- 파일럿 참여자 5명의 결과에 대해 완료시간, 카드 생성, 행동 선택, 수정횟수를 반복 측정한다.

### 4. 순서도로 검증

**종이 시뮬레이션 예시(아직 API 실험 결과가 아님)**

1. 입력: `항공물류 전공`, `AI 수학 독학 노트`, `Solar를 연결한 MindHub 프로토타입`, 목표직무 `AI 서비스 기획자`.
2. 예상 추출: `물류 도메인 이해`, `AI 기초학습`, `AI API 기반 프로토타이핑`과 각각의 원문 근거.
3. 사용자가 앞의 두 항목은 확인하고, 과장된 `AI 모델 개발` 후보는 거절한다.
4. 직무표 비교 결과: 강점은 문제발견·도메인 연결·프로토타이핑, 격차는 사용자 검증·데이터 지표·기관 개인정보 설계로 계산된다.
5. 행동 3개: `사용자 인터뷰 학습자료`, `5명 인터뷰 미니프로젝트`, `상담사에게 Gap Brief 유용성 확인`.
6. 결과: 근거 없는 `AI 모델 개발`은 카드에 들어가지 않고, 사용자가 선택한 다음 행동이 카드에 남는다.

**검토 결과:** 정상 흐름, 낮은 신뢰도, 사용자 거절, API 실패, 3회 미통과의 분기까지 논리적으로 연결된다. 실제 API 응답형식·속도·오류복구는 MVP 구현 후 테스트 결과로 교체해야 한다.

6. 시연 중 API 장애 → 데모 데이터임을 명확히 표시하는 폴백을 준비한다.

## 7단계. 결과 시연 · 발표

### 1. 발표 스크립트 (발표 흐름)

**문제:** 저는 항공물류를 전공했지만 AI 수학, 웹, 아두이노를 따로 공부했습니다. 배움은 쌓였지만 학적 밖의 경험이라 ‘내가 무엇을 할 수 있는지’로 설명하는 데 큰 에너지가 들었습니다. 쉬었음 청년과 전환자도 비슷합니다. 노동시장은 빠르게 변하지만 학적과 자격은 정적이고, 그 사이를 연결하는 비용을 개인이 혼자 부담합니다.

**핵심 아이디어:** GapProof는 공백을 지우는 서비스가 아니라 공백 속 경험을 증거로 바꾸는 서비스입니다. Solar가 한국어 경험에서 역량 후보와 원문 근거, 빠진 정보를 구조화하고, 사용자가 확인한 항목만 목표직무 격차와 다음 행동으로 연결합니다.

**해결 과정:** 경험 입력 → Solar 구조화 → 사용자 확인 → 증거등급 → 직무 격차 → 행동 3개 → GapProof 카드와 상담용 Gap Brief 순서로 설계했습니다. AI가 진로를 단정하지 않고, 근거 없는 역량을 검증됐다고 말하지 않는 것이 핵심 원칙입니다.

**시연:** 항공물류 전공과 AI 독학, Solar 프로젝트 경험을 넣습니다. 사용자는 과장된 후보를 거절하고 실제 역량만 확인합니다. GapProof는 AI 서비스 기획자와의 격차를 보여주고, 이번 주에 할 학습·프로젝트·상담 행동을 하나씩 제안합니다. 상담사는 1쪽 요약으로 바로 다음 행동을 논의합니다.

**배운 점·개선:** 미래를 정확히 예측하는 것보다, 불확실한 미래에도 다시 움직이게 하는 작은 증거와 행동이 중요합니다. 파일럿에서는 청년 5명과 상담사 2명에게 실제 완료시간과 유용성을 확인하겠습니다.

> 선택적 개인 서사 15초: “재수·삼수와 아르바이트, 어머니의 투병과 사별을 지나면서도 배움을 놓지 않았습니다. 하지만 노력 자체보다 그것을 다음 기회로 연결하는 구조가 필요하다는 것을 배웠습니다.” 공개 범위는 발표 전 최종 결정한다.

### 2. 시연 시나리오 / 실행 결과

**시연 시나리오(구현 예정)**

1. 시작 화면에서 저장·공유 동의를 선택한다.
2. `항공물류 전공`, `AI 수학 독학`, `Solar 기반 MindHub 제작` 경험을 입력한다.
3. Solar가 역량 후보·원문 근거·추가질문을 카드로 만든다.
4. 사용자가 `AI 모델 개발자`처럼 과장된 후보는 거절하고 나머지를 확인한다.
5. 목표직무 `AI 서비스 기획자`를 선택한다.
6. 강점 3개와 격차 3개가 나타난다.
7. 학습 1개, 미니프로젝트 1개, 상담 행동 1개 중 이번 주 행동을 고른다.
8. GapProof 카드와 상담사용 Gap Brief를 나란히 보여준다.
9. 마지막에 원문 삭제와 통계 공유 철회가 가능한 화면을 보여준다.

**현재 실행 결과:** 클릭 가능한 샘플 화면 골격을 구현 중이며 실제 Solar·저장 기능은 미구현이다. 2026-07-28 제출 후보에서 실제 화면·소요시간·성공/실패 결과로 교체한다.

**현재까지 잘한 점:** 문제를 단순한 강의 추천이 아니라 `경험 → 근거 → 격차 → 행동 → 상담`의 닫힌 흐름으로 좁혔고, 개인용 서비스와 기관 도입가치를 함께 정의했다.

**현재 아쉬운 점:** 핵심 고객과 대표 직무가 아직 가설이며, Solar 추출 정확도와 상담현장의 지불의사는 검증하지 못했다.

**배운 점:** 대상 범위를 넓히는 것보다 쉬었음 청년이라는 날카로운 시작점과 재사용 가능한 ‘증거 구조’를 만드는 것이 중요하다. 수료증보다 원문 근거, 사용자 확인, 평가 상태가 함께 있어야 신뢰할 수 있다.

**개선할 점:** 2026-07-23 멘토링에서 제출 트랙·첫 고객·MVP 범위를 확정하고, 2026-07-28까지 1차 제출 후보를 만든다. 7월 29일 1차 제출, 7월 31일 2차 제출을 거쳐 8월 3일 최종 제출 후 수정 동결(8/4 담당자 취합)한다. 예선은 서면평가이므로 산출물이 문서만으로 이해되게 만들고, 본선 현장 PT용 3분 데모를 별도로 준비한다. 청년 5명·상담사 2명의 누적 관찰 결과로 문장, 화면, 추천규칙을 수정하며, 실제 구현·테스트·링크가 생길 때마다 이 문항을 사실에 맞게 갱신한다.
