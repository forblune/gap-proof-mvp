# professor-review

GapProof 화면을 지도교수/심사자 관점에서 평가하는 스킬. 코드를 고치지 않고 **평가만** 한다 — 수정은 `design-loop`가 담당한다.

## 절차

1. `npm run dev`가 이미 떠 있지 않으면 `run` 스킬 방식으로 로컬 서버를 띄운다 (기본 `http://localhost:3000`).
2. Playwright(devtools MCP 또는 `@playwright/test` 브라우저)로 아래 화면을 390px·768px·1024px·1440px에서 각각 스크린샷·DOM 스냅샷을 확보한다.
   - `/` (홈), `/demo` (게이트+샘플 여정 STEP0~4), `/why`, `/how-it-works`, `/technology`, `/guide`
3. 아래 7개 항목을 **독립적으로** 채점한다(한 항목의 감점이 다른 항목 점수에 영향을 주지 않게 각 항목을 별도로 훑는다). 각 항목은 1~5점 + 구체적 근거(파일·셀렉터·화면 위치) + 개선 제안.

   1. **문체(Tone)** — 존댓말 일관성, 과장·단정 표현(예: "취업 보장", "적성 판정") 여부, 대상 독자(심사자/멘토)에게 맞는 어휘 수준.
   2. **시각적 위계(Visual hierarchy)** — h1~h3 크기·굵기 대비, CTA 버튼의 시각적 우선순위, 섹션 간 여백으로 흐름이 읽히는지.
   3. **텍스트 밀도(Text density)** — 한 화면에 몰린 문단 길이, 스캔 가능한 bullet/카드 구조 사용 여부, 390px에서 스크롤 없이 핵심을 파악할 수 있는지.
   4. **이미지·아이콘(Imagery/icons)** — 아이콘과 텍스트의 의미 일치, 장식용 이미지의 alt 처리, 아이콘 세트 일관성(굵기·스타일 혼용 여부).
   5. **타이포그래피(Typography)** — 폰트 크기 스케일의 일관성, 줄간격, 강조(bold/italic) 남용 여부, 대비(axe color-contrast 결과 인용).
   6. **반응형(Responsive)** — 390/768/1024/1440에서 가로 스크롤 유무, 터치 타깃 크기(최소 44px), 모바일 메뉴/드로어 동작.
   7. **기술 설명(Technical explanation)** — `/technology`, `/how-it-works`에서 Solar 연동·데이터 처리·근거 검증 로직을 심사자가 이해할 수 있게 설명하는지, 과장 없이 한계(샘플 모드, 저장 정책)를 명시하는지.

4. 항목별 점수를 합산하지 말고 **최저 점수 항목부터** 정렬해 보고한다. 다음 단계(`design-loop`)가 우선순위를 그대로 가져다 쓸 수 있어야 한다.

## 출력 형식

```
## professor-review 결과 (YYYY-MM-DD)

| 항목 | 점수(1-5) | 근거 | 개선 방향 |
|---|---|---|---|
| 문체 | ... | ... | ... |
| 시각적 위계 | ... | ... | ... |
| 텍스트 밀도 | ... | ... | ... |
| 이미지·아이콘 | ... | ... | ... |
| 타이포그래피 | ... | ... | ... |
| 반응형 | ... | ... | ... |
| 기술 설명 | ... | ... | ... |

### 우선순위 낮은 순 (개선이 시급한 순)
1. ...
2. ...
```

## 주의사항

- 이 스킬은 **코드를 수정하지 않는다.** 발견한 문제를 고치려면 `design-loop`를 호출하라고 안내한다.
- 실제 배포(운영 도메인)에 대해 평가하지 말고 로컬 dev/preview 화면만 사용한다.
- 스크린샷·DOM 검사에는 Playwright MCP 또는 `npx playwright test`로 만든 `tests/e2e/screenshots.spec.ts` 산출물을 활용할 수 있다.
